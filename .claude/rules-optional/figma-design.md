# Figma ↔ тема

Макет — источник значений, тема — их реализация. Нет MCP `figma` в сессии — сказать об этом и не верстать «на глаз» (решение 007). Макет из Claude Design — правило `design` (решение 023).

## Дизайн в Figma

Скиллы `figma-use` (обязателен перед любым `use_figma`), `figma-generate-library`, `figma-generate-design`, `figma-create-new-file`.

1. Порядок: переменные (цвет, типографика, отступы, радиусы) → компоненты → страницы. Страницу без переменных не собирать.
2. Имя переменной — будущий слаг `theme.json`: `color/primary` → `primary`, `space/40` → `40`, `font-size/lg` → `lg`. Латиница, kebab-case.
3. Отступы — та же шкала, что `spacing.spacingSizes` темы. Кегль и отступ, который меняется от мобильного к десктопу, — пара значений mobile/desktop (в теме это `fluid: { min, max }`; когда fluid — `scss-bem` → «Fluid»).
4. Фреймы страницы — минимум 375, 768, 1440 (брейкпоинты стартера, правило `layout-check`); имя `Страница / ширина`. Auto-layout, без абсолютного позиционирования контента.
5. Слой секции называть как будущий блок или паттерн: `{stem}-hero`, `{stem}-hero__title`. Контент шириной 1200px, секции на всю ширину (решения 010, 011).
6. Ссылку на файл и список фреймов — в `ACCESS.md` → Figma сразу после создания.

## Макет → тема

Скилл `figma-design-to-code`.

- Переменные Figma → пресеты `theme.json` (`color.palette`, `typography.fontSizes`, `spacing.spacingSizes`) одной правкой, не россыпью значений по SCSS.
- В разметке и SCSS — только пресеты (`var:preset|color|primary`, `var(--wp--preset--…)`), не hex и px из макета.
- Значения нет среди токенов — сначала токен в Figma и `theme.json`, потом использование. Разовый px — только с комментарием-причиной.
- Секция макета → pattern; повторяемый элемент с логикой → блок. Графика — экспорт SVG/WebP в тему, не ссылки на figma.com.
- Сверка с макетом — правило `layout-check`, пункт «Макет».
