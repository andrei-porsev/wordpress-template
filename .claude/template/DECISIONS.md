Не путать с `git log`: там **что** менялось, здесь — **почему** выбран подход

## Журнал

## 028 — 2026-10-15 — Инициализация по этапам и типам проекта

- **Решение:** `project-init` — 10 этапов (тип, бриф, доступы, разведка и безопасность, стек, пакеты, сайт и браузер, заливка, сводка, проверка), файл на этап; 7 типов проекта в два уровня (новый: нужен дизайн / дизайн есть; существующий: доработка / редизайн / переезд / SEO и скорость) + признак «после другого разработчика» → аудит. Вопросы — со строкой «Зачем:»; технические поля предлагает агент; ответы копятся в `.claude/.state/init.json`, запись — после одной сводки с пометками источника. Пакеты услуг — `.claude/packages.json`. Существующий сайт — проверка безопасности до скачивания (`security-check.md`).
- **Причина:** линейный опрос задавал всем одни и те же 13+ технических вопросов, писал в файлы по ходу и не учитывал, что у клиентского сайта сначала нужны доступы, копия и проверка. Пользователь — разработчик, не маркетолог: бриф и SEO агент ведёт сам.
- **Следствие:** часть шагов опирается на скрипты части C плана (`project-base/plans/init-redesign.md`) — до них запасной путь через `ssh-exec.mjs` / `sftp-sync.mjs` или ручной шаг. Хук не знает режима `local` → локальная работа записывается как `manual (local)`. Заменяет 025.
- **Статус:** действует

## 027 — 2026-10-15 — Профиль проекта, ядро `CLAUDE.md`, два файла решений

- **Решение:** итог `project-init` — «Профиль проекта» в шапке `project-base/INDEX.md` (тип, вид сайта, главные действия посетителя, языки, посетители, окружения, заливка, пакеты, стек, брейкпоинты темы); агент читает профиль, а не определяет стек заново. `CLAUDE.md` — только ядро правил; лестница выбора подхода — в `project-init`. Решения шаблона — `.claude/template/DECISIONS.md`, решения сайта — `project-base/DECISIONS.md`.
- **Причина:** `CLAUDE.md` (~12,5 КБ) и растущий журнал решений грузились в контекст каждой задачи, хотя большая часть нужна только при старте или архитектурной работе. Решения шаблона и проекта в одном файле мешают обновлять шаблон в старых проектах.
- **Следствие:** при обновлении шаблона `.claude/template/` заменяется целиком, `project-base/DECISIONS.md` не трогается. Строку `- Название / домен:` в шапке `INDEX.md` читает хук `stop-map` — не переименовывать. План переделки — `project-base/plans/init-redesign.md`.
- **Статус:** действует

## 026 — 2026-10-15 — Дампы БД не в git

- **Решение:** дамп БД остаётся на сервере (`../claude-backup-<время>.sql` от хука или бэкап хостинга); `project-base/dumps/` исключён в `.gitignore`. Тяжёлые исходники дизайна и медиа (`psd`, `ai`, `fig`, `sketch`, `xd`, `mp4`, `mov`, `zip`, `raw`) в `project-base/` тоже не в git — облачная папка, ссылка в `ACCESS.md`.
- **Причина:** в БД персональные данные посетителей и клиентов (заказы, пользователи, письма); копия в репозитории и на GitHub — лишний риск и вопрос GDPR. Большие бинарные файлы раздувают репозиторий навсегда.
- **Следствие:** уточняет 001 — дампы больше не коммитим, скрины в `screenshots/` по-прежнему в git (сжатые). Перенос БД на локальный сайт — осознанная операция человека, не побочный файл в проекте.
- **Статус:** действует

## 025 — 2026-10-14 — Тип проекта как первый вопрос старта

- **Решение:** `project-init` первым спрашивает тип проекта: новый — нужен дизайн / новый — дизайн есть / клиентский — доработка / клиентский — редизайн (рестайл или новая тема). Каждый тип — свой маршрут в `.claude/skills/project-init/types.md`: порядок блоков A–F, что пропустить, предзаполнение, стеки по умолчанию. Тип пишется в `INDEX.md` → «Проект». Каждый вопрос опроса — со строкой «Зачем:» и пояснением терминов.
- **Причина:** единый линейный опрос задавал всем одни и те же вопросы; у нового сайта нет кода для анализа, у клиентского сначала нужны доступы и копия сайта, у редизайна — выбор глубины и защита живого сайта. Пользователь не всегда помнит, за что отвечает вопрос.
- **Следствие:** новый тип проекта — новый раздел в `types.md`, не правка общих блоков. Смена архитектуры при редизайне — отдельная запись в `DECISIONS.md` проекта. Старая тема при «новой теме» в `project.json` не попадает.
- **Статус:** отменено, заменено 028

## 024 — 2026-10-14 — GSAP для анимаций, стек `motion`

- **Решение:** сложные анимации (таймлайны, ScrollTrigger, SplitText, Flip) — GSAP; простые — CSS. Библиотека — локальная копия в `assets/lib/gsap/<версия>/` темы, подключение на `wp_enqueue_scripts` с `defer` и только на страницах с анимацией. Скиллы `gsap-core`, `gsap-timeline`, `gsap-scrolltrigger`, `gsap-plugins`, `gsap-utils`, `gsap-performance` из `greensock/gsap-skills` (MIT) — стек `motion`; WP-специфика — правило `motion`. Источник `gsap` добавлен в `sources` по просьбе пользователя.
- **Причина:** нужен «вау-эффект» без дизайнера; GSAP с 2025 года бесплатен со всеми плагинами, включая коммерческое использование. Скиллы GreenSock не знают WordPress, не требуют `prefers-reduced-motion` и советуют GSAP по любому поводу. CDN отброшен: GDPR, лишний DNS, версия вне git. `gsap-react` и `gsap-frameworks` не взяты: темы на vanilla JS.
- **Следствие:** лицензия самой GSAP — GreenSock Standard No-Charge License, не MIT; версию библиотеки в теме обновляем вручную и пишем в `INDEX.md`. Паттерны остаются без JS, анимация навешивается по стилю блока или BEM-признаку. Обязательны `gsap.matchMedia()` с reduced motion и видимость контента без JS.
- **Статус:** действует

## 023 — 2026-10-14 — Claude Design как источник макета, стек `design`

- **Решение:** макет может прийти из Figma (решение 007) или из Claude Design (`/design` в Claude Code, handoff из claude.ai либо экспорт HTML/ZIP в `project-base/design/`; дизайн-система клиента — `/design-sync` из темы, `theme.json` — источник правды). Экспорт Claude Design — прототип: из него берём значения в пресеты `theme.json` / SCSS, разметку пишем заново по `markup-layout` и `scss-bem`. Без макета — скилл `frontend-design` (`anthropics/skills`, Apache-2.0): план токенов и раскладки, «да» пользователя, потом код. Правило `design`, ссылка — `ACCESS.md` → «Дизайн (Claude Design)», вопрос — `project-init` → F3b. Источник `anthropic` добавлен в `sources` по просьбе пользователя.
- **Причина:** решение 007 запрещало вёрстку без MCP Figma, и макет из Claude Design агент мог бы отклонить. Пользователь — разработчик без дизайнера; без слоя эстетики вёрстка выходит шаблонной. `web-design-guidelines` (Vercel) отброшен: при каждом запуске скачивает правила из интернета и исполняет их как инструкции (против правила `safety`), лицензии в репозитории нет.
- **Следствие:** 007 действует для Figma; для Claude Design MCP не нужен. Эстетика `frontend-design` важнее типографических приёмов `wp-patterns`. Шрифты — только локально.
- **Статус:** действует

## 022 — 2026-10-08 — Скиллы по манифесту: апстрим, стеки, обновления

- **Решение:** `.claude/skills.json` — источник правды по скиллам: репозиторий и путь апстрима, коммит, хеш дерева, хеш содержимого, стеки (`fse`, `woo`, `figma`, `content`, `seo`, `quality`…). Скрипт `project-ops/scripts/skills-sync.mjs` подключает стек (`activate`), проверяет апстрим (`check`), показывает план и обновляет (`update`, применение — `--apply` после «да» пользователя). Хук `SessionStart` раз в сутки сообщает агенту об обновлениях подключённых скиллов. Ядро — `project-init`, `project-structure`, `project-ops`; `wordpress-router` и `wp-project-triage` — стек `triage` в `skills-optional/`. Плагины с собственным рантаймом (`claude-seo`) не копируем: включаются в `settings.json` по стеку, обновляет Claude Code. `@playwright/mcp` закреплён по версии.
- **Причина:** копии скиллов не знали, откуда и какой версии они взяты, и молча устаревали (к октябрю 2026 из 12 копий WP-скиллов устарели 7, в `wp-performance` — неработающая команда `wp doctor check`). Полный копипаст популярных каталогов (тысячи скиллов) забивает контекст и смешивает похожие триггеры; нужен короткий набор под стек проекта. Автоматическое обновление без просмотра отброшено: скилл — инструкция агенту с доступом к серверу.
- **Следствие:** локальные правки в чужом скилле блокируют его обновление — дорабатывать отдельным правилом или скиллом, либо переводить скилл в `source: "local"`. Сеть — только `git`. Хук и разрешения скрипта вносит человек в `.claude/settings.json` (решение 019). Бриф для контента — `.claude/product-marketing.md` (путь, который читают скиллы `content`), а не `project-base/`: исключение из 001. Новый источник скиллов в `sources` добавляет человек.
- **Статус:** действует

## 021 — 2026-09-20 — Автодамп, журнал, лимит попыток, изоляция браузера

- **Решение:** перед первым подтверждением изменяющей команды WP-CLI за сессию `guard-wpcli` сам делает `wp db export ../claude-backup-<время>.sql`; `.claude/.state/audit.log` пишет заливки, откаты, блокировки и решения по WP-CLI; `post-edit` считает неудачи по файлу и после 3-й требует остановиться; Playwright запускается с `--isolated`, домены проекта добавляет `project-init` в `--allowed-origins`.
- **Причина:** напоминание про дамп не срабатывало само; без журнала инцидент не разобрать; агент мог бесконечно чинить один файл; сессии браузера не должны переходить между проектами.
- **Следствие:** `--allowed-origins` границей не служит (по документации Playwright, не влияет на редиректы), поэтому правило `safety` запрещает сторонние сайты отдельно. Дамп остаётся на сервере до ручной очистки. Автодамп делается и тогда, когда пользователь потом откажет запрос.
- **Статус:** действует

## 020 — 2026-09-20 — Проверки качества и обязательная проверка вёрстки

- **Решение:** `post-edit` запускает `phpcs` (стандарт WordPress, `phpcs.xml.dist`) для PHP и `stylelint` (`.stylelintrc.json`, BEM, без `!important`, максимум вложенности 4) для SCSS, если инструмент есть; результат уходит агенту, заливку не блокирует. Правило `layout-check`: проверка по брейкпоинтам стартера (для каркаса и глобальных стилей — нижние границы всех диапазонов 320/375/480/768/992/1024/1200/1440, для локальной правки — только затронутые и соседние диапазоны; на 1px меньше — для затронутых), переполнение по ширине через `browser_evaluate`, консоль и сеть без ошибок, семантика, сверка с Figma.
- **Причина:** синтаксис и работоспособность страницы хук проверяет, а соответствие стандартам и качество вёрстки — нет.
- **Следствие:** `phpcs` не входит в зависимости шаблона (нужны composer и WPCS), `project-init` спрашивает, ставить ли. Конфиг `stylelint` подстроен под заготовку `_starter` (camelCase-миксины допустимы, `!important` только с `stylelint-disable-next-line`). Нет инструмента — проверка пропускается молча.
- **Статус:** действует

## 019 — 2026-09-20 — Автономность: acceptEdits и защита от самого агента

- **Решение:** `defaultMode: acceptEdits`; `allow` расширен (git status/diff/log/add/commit, `npm run build|start`, `php -l`, документация WordPress/Woo/ACF/MDN); `git push` и правки конфигов доступа — `ask`; `deny` на разрушающее и сетевое локально (`rm -r`, `git reset --hard`, `git clean`, force-push, `curl`, `wget`, `Invoke-Expression`, `sudo`) и на правку `.claude/hooks/`, `.claude/settings*.json`, `.git/`. Новый `guard-bash` переносит границу `guard-paths` на запись через Bash и PowerShell.
- **Причина:** запросы на каждую правку мешают автономной работе, а сам агент мог бы снять свои ограничения.
- **Следствие:** защитные механизмы правит только человек; менять их можно только вручную в редакторе (`deny` на Edit действует всегда; `CLAUDE_TEMPLATE_DEV=1` отключает лишь проверки хуков). Запись из скриптов (`node script.mjs`, `npm run build`) хуки не видят.
- **Статус:** действует

## 018 — 2026-09-20 — Файлы правим только локально

- **Решение:** запись в файлы на сервере запрещена: охранник `guard-wpcli` блокирует `>`, `tee`, `sed -i`, `cp`, `mv`, `rm` и подобное, а чтение секретов (`wp-config`, `.env`, ключи) запрещает; прямые `ssh` / `scp` / `sftp` / `rsync` — в `permissions.deny`. На сервер ходят только `ssh-exec.mjs` (WP-CLI, чтение логов и каталогов) и `sftp-sync.mjs`.
- **Причина:** правка на сервере в обход локальных файлов расходит копии, обходит git, `guard-paths`, бэкап и откат `post-edit`, карту проекта.
- **Следствие:** любую правку кода агент делает локально, а на сервер её заливает хук или `upload`. Чтение оболочкой (`tail`, `cat`, `ls`, `grep`, `php -v/-l`) охранник пускает без запроса. Обход через `bash -c` или другой канал охранник не разбирает.
- **Статус:** действует

## 017 — 2026-09-20 — WP-CLI: охранник и только чтение без запроса

- **Решение:** хук `guard-wpcli` (PreToolUse на Bash) разбирает команду после `ssh-exec.mjs --`: разрушающие блокирует, меняющие сайт или БД отдаёт на подтверждение, чтение пропускает. В `permissions.allow` — только точечные команды чтения (список в `WORKFLOW.md` → 4). Скилл `wp-wpcli-and-ops` обязателен при WP-CLI = да. Перед командой, меняющей БД, — дамп `wp db export`.
- **Причина:** запрет опасных команд держался на тексте; при этом даже безобидный `wp plugin list` требовал подтверждения.
- **Следствие:** охранник видит только вызовы через `node …ssh-exec.mjs -- …` в Bash; собственный `ssh` и другие каналы в шаблоне не предусмотрены. Дамп автоматически не делается — это шаг агента по правилу. Сбой хука не блокирует, поэтому в `allow` нет общего `wp *`. Упоминание команды в тексте (heredoc, echo) охранник не трогает.
- **Статус:** действует

## 016 — 2026-09-20 — Скиллы и правила: ядро и опциональные

## 012 — 2026-09-20 — Заливка агентом: `guarded-auto` по умолчанию (заменяет 005)

- **Решение:** режим в `ACCESS.md` → «Заливка»: `guarded-auto` (хук заливает каждую правку с проверкой и откатом), `stage-auto` (то же на stage), `manual` (как в 005: по команде или «да»). `uploadOnSave` в Cursor не трогаем — это ручная работа.

## 011 — 2026-09-03 — `__inner` и `alignfull` вместо своих дублей

- **Решение:** если у блока обязательны `__inner` / `__inner-container` и `alignfull` — вешаем наши 90%/1200px и full-parent на эти классы. Свои `{stem}-container` и `--full` не добавляем рядом.
- **Причина:** вторая обёртка ломает InnerBlocks и валидацию Gutenberg; ядро уже даёт inner и выравнивание.
- **Следствие:** `section-shell` стилизует `&__inner` и `.alignfull`. `{stem}-container` — только где inner нет. Стили ядра у `.alignfull` переопределяем специфичностью, не `!important`.
- **Статус:** действует

## 010 — 2026-09-03 — Каркас секции и контейнера

- **Решение:** контент одной ширины: секция на 100% (сброс margin/padding, `padding-block` через fluid при двух значениях), внутри `{stem}-container` (90% / max-width 1200px). Семантика HTML без дубля `header`/`footer` ядра. Layout — flex/grid и `gap`. Rules `markup-layout`, `scss-bem`.
- **Причина:** иначе каждая секция задаёт свою ширину; `supports.spacing` не даёт одну колонку и fluid `padding-block`. От фиксированного «всегда fluid-fs» отказались: миксин только если в макете два значения.
- **Следствие:** ширину колонки не вешать на секцию. Gutenberg: колонка на `__inner`, полная ширина на `alignfull` (№011). Иначе `{stem}-container`. Именованные брейкпоинты раньше сырых `up()`/`down()`. `!important` только если специфичность не достаёт.
- **Статус:** действует

## 009 — 2026-09-02 — Папка на каждый пакет, внутри фронт и бэк

- **Решение:** у каждой своей темы и каждого своего плагина — своя папка `{slug}/`, внутри слои `front/` и `back/` если они есть. Пакетов может быть несколько.

- **Статус:** действует

## 005 — 2026-09-02 — Заливка агентом только при SSH и с согласия

- **Решение:** если SSH есть, агент сам обновляет файлы на сервере (`sftp-sync upload`). Без команды («залей» и т.п.) и без «да» — не заливает. Нет SSH — агент сервер не трогает, человек сохраняет в редакторе (`uploadOnSave`).
- **Причина:** иначе каждая правка сразу уезжает на живой сайт; пользователь должен решать, когда сервер обновлять.
- **Следствие:** compile/build остаются локальными до согласия. WP-CLI по SSH — тоже по команде или «да».
- **Статус:** действует

## 004 — 2026-09-02 — Память доступов в ACCESS.md

- **Решение:** любой доступ, который пользователь дал агенту (SSH, SFTP, WP-CLI, админка), сразу пишется в `ACCESS.md` и в `.vscode/ssh.json` / `sftp.json`. Перед вопросом агент читает ACCESS.md. Пароль в чат не повторять.
- **Причина:** иначе каждый чат заново спрашивает хост и логин, хотя они уже были.
- **Следствие:** интерактивный `ssh` запрещён (агент — `ssh-exec.mjs`). Пустой host в ssh.json наследует SFTP. В ACCESS.md пароль не дублировать, если он уже в json.
- **Статус:** действует

## 003 — 2026-09-02 — Канон операций в skill `project-ops`
