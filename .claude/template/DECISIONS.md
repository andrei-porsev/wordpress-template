## Журнал

## 049 — 2026-10-19 — Диапазон fluid и пресеты theme.json (уточняет 040, 047)

- **Решение:** миксины `fluid`, `fluid-fs`, `fluid-var`, `fluid-fs-var` по умолчанию растят от 320 до 1600 px — как fluid-типографика WordPress (`$cltm-fluid-min-vw` / `$cltm-fluid-max-vw`); свой диапазон — аргументами `$bp-min` / `$bp-max` (у `fluid-fs` раньше их не было). FSE: `settings.typography.fluid.minViewportWidth / maxViewportWidth` — явно, как у миксина. Размеры для редактора — пресеты `fontSizes` с `fluid: { min, max }`, интерфейс — миксин; роль с пресетом — через `var(--wp--preset--font-size--…)`. Ссылки на любые пресеты в `theme.json` и разметке блоков — `var:preset|<тип>|<слаг>`.
- **Причина:** вопрос пользователя по пилоту SiteA (5 мест шрифтов в `theme.json` через `var(--wp--preset--…)` — та же проблема, что с цветами в 047): `var:preset|font-size|…` только ссылается на пресет, пара моб/деск и fluid задаются в самом пресете. Без явного диапазона WordPress растит шрифт от 320 до `layout.wideSize` или 1600, а миксин — 768 → 1440: размеры из `theme.json` и SCSS расходились бы. Пользователь: диапазон миксина подстроить под WordPress, свои величины — при необходимости.
- **Следствие:** `_starter` (`_variables`, `_mixin`), `scss-bem` → «Fluid», `fse-theme`, `site-design`, паспорт, README. Проверено: 26 → 44 → `clamp(1.625rem, 1.3438rem + 1.4063vw, 2.75rem)`; с `$bp-min: 768px, $bp-max: 1440px` — прежний результат. Проекты с уже скопированным `abstracts/` не меняются; у SiteA свой диапазон — в паспорте. В 040 строка о диапазоне уточнена этим решением.
- **Статус:** действует

## 048 — 2026-10-19 — Свой код только через Edit / Write

- **Решение:** файлы темы и своих плагинов (текстовый код: php, scss, css, js, json, html…) агент меняет только Edit / Write; массовая замена — серией Edit. `guard-bash` блокирует запись в них через оболочку (`sed -i`, `>`, `tee`, `cp` / `mv` в цель, `touch`, PowerShell-аналоги) и разовым скриптом (`node -e`, `node -` / heredoc, который пишет в `wp-content/`). Можно: сборка (`assets/css/`, `build/`, `dist/`, `.map`), бинарные и прочие файлы (картинки, шрифты, svg), `rm`, `mkdir`, копирование **из** темы. Разовые скрипты на Python (`-c`, `-`, heredoc) блокируются всюду; запуск готового `.py` (глобальные SEO-скиллы) — нет. С `CLAUDE_TEMPLATE_DEV=1` эти проверки, как и прочие `guard-bash`, выключены.
- **Причина:** пилот SiteA, задача color-9: четыре SCSS-файла правлены через Bash — хук `post-edit` их не видел (без линтера, копии с сервера, отката), агент залил их сам. На PHP-шаблоне в `guarded-auto` тот же приём выкатил бы ошибку без отката. Python агент пытался запустить, хотя в Git Bash `python` — заглушка Microsoft Store («не найден»), и потерял вызовы; пользователь: «сюрпризов не надо».
- **Следствие:** `CLAUDE.md` → «Заливка и проверка»; хук и 14 проверок selftest — патч `shell-edits` (применил человек, selftest 93 / 93). Запись из готового скрипта (`node script.mjs`) охранник по-прежнему не видит — держит правило.
- **Статус:** действует

## 047 — 2026-10-19 — Формат цвета в коде

- **Решение:** hex — только в палитре `theme.json` и как запасное значение. SCSS — `var(--wp--preset--color--<слаг>, <hex>)`; внутри `theme.json` (`styles`) и в разметке блоков — `var:preset|color|<слаг>`. Прозрачность: чёрный и белый — `rgb(0 0 0 / 20%)`, цвет палитры — `color-mix(in srgb, var(…) N%, transparent)`; `rgba()` через запятые не используется (stylelint). Слаги — с дефисом перед цифрой.
- **Причина:** вопрос пользователя при выносе `#faf7f0` в `color-9` на SiteA. Проверено на сайте: `--wp--preset--color--color-9` отдаётся. WordPress сам вставляет дефис перед цифрой в имя переменной (`color9` → `--…--color-9`), и ссылка из SCSS по слагу без дефиса не находит переменную; `var(--wp--preset--…)` внутри `theme.json` работает, но редактор показывает «свой цвет» без привязки к палитре (в SiteA так 9 мест).
- **Следствие:** `site-design` → «Границы», `fse-theme`. Старые места темы — по паспорту дизайна, раздел «Отклонения»; переделка — по просьбе.
- **Статус:** действует

## 046 — 2026-10-19 — Снимки «было → стало» и сравнение

- **Решение:** для заметной правки (044) и правки каркаса — пара снимков: «было» до первой правки (при коротком `manual` — до `deploy`), «стало» после, те же адрес и ширины. Перед **каждым** снимком — подготовка (`layout-check` → «Было → стало»): `reducedMotion: reduce`, догрузка ленивых картинок, шрифты, скрытие «динамических зон» из паспорта дизайна и полосы прокрутки. `shot-diff.mjs diff` сравнивает по слегка размытым снимкам (размытие 1, порог 72, клетка 16 px от 3 пикселей), печатает долю изменённого, области и одиночные клетки отдельно, пишет картинку-разницу; разная ширина — «несопоставимы». Область вне затронутого элемента — регрессия до «готово». Пары и разница показываются пользователю файлами. Хранение — `.claude/.state/reports/shots/<задача>/`, старше 180 дней удаляются при любом запуске, раньше — `clean <задача>` / `--all` по просьбе. Лимит снимков на задачу — 12 (6 пар).
- **Причина:** отчёт без картинок пользователь проверяет сам; регрессии на соседних участках на глаз по одному снимку не видны. Копии лежат на машине разработчика — хранить дольше 30 дней не дорого (пожелание пользователя: полгода или по команде).
- **Следствие:** проба на SiteA: без подготовки — 15% ложной разницы (ленивые фото, полоса прокрутки), подготовка один раз на два снимка — пропали фото новостей у второго; с подготовкой перед каждым и размытием — 0,02%: одна область (заголовок) и 5 одиночных клеток. Разрешение `shot-diff.mjs*` в `permissions.allow` — патч `shot-diff-allow` (применил человек, selftest 79 / 79). Раздел «Динамические зоны» в паспорте дизайна. Тест `test-shot-diff`.
- **Статус:** действует

## 044 — 2026-10-19 — План до правки

- **Решение:** мелкая правка (1–2 файла, существующий элемент, очевидное исполнение, без новых значений дизайна, файлов, хуков, зависимостей) — одна строка «Делаю: …» и сразу работа. ## 043 — 2026-10-19 — Единицы: rem, em, px

- **Решение:** кегли и отступы (`padding-block`, `gap`, поля компонентов) — rem; в коде числа из макета в px, переводят `to-rem()` и `fluid` / `fluid-fs` (база `$cltm-rem-base: 16`). `fluid` на выходе — `clamp(<min>rem, <смещение>rem ± <наклон>vw, <max>rem)`. em — то, что привязано к своему тексту (поля и иконка кнопки, `letter-spacing`, отступы элементов контента); `line-height` — без единиц; px — рамки, `outline`, тени, радиусы, мелкие детали, `max-width` контейнера, брейкпоинты, значения из полей редактора (`fluid-var`). Тема на px не переводится без просьбы: новое — в системе сайта, `fluid(…, $unit: px)`, в паспорте — «отклонение».
- **Причина:** px игнорирует настройку размера шрифта в браузере (слабовидящие, требования доступности в ЕС); при масштабе px и rem ведут себя одинаково. Чистый vw при масштабе не растёт — смещение в rem это исправляет. Старый `fluid` выдавал только px, а `$unit: rem` ломал формулу (разница значений умножалась на px-часть).
- **Следствие:** `_starter/scss/abstracts/_mixin.scss` — `to-rem()`, новый `fluid` (проверено: 26 → 44 → `clamp(1.625rem, 0.3393rem + 2.6786vw, 2.75rem)`, убывающая пара, одинаковые значения, `!important`, `$unit: px`), устаревший в Sass `if()` заменён на `@if`. Функция названа `to-rem`, а не `rem`: у CSS есть своя `rem()`. Хуки видят Write / Edit / MultiEdit, правки и сборка через Bash (SCSS, `npm run build`, `sed`) их обходят: CSS и `build/` агент заливает сам после сборки. Сбой самого хука ход не блокирует (кроме явных ошибок проверки).
- **Статус:** действует

## 014 — 2026-09-20 — `project.json` как единственный источник слагов

- **Решение:** `project-base/project.json` (`stem`, `themes`, `plugins`, `muPlugins`, `blocks`); `gen-whitelist.mjs` пишет из него whitelist в `.gitignore` (между маркерами) и `ignore` / `watcher` в `.vscode/sftp.json`. Хук `guard-paths` читает тот же файл.
- **Причина:** раньше слаги подставлялись вручную в 3–4 места и расходились; второй плагин или блок означал правку всех мест.
- **Следствие:** руками эти списки не правим. Добавился пакет — строка в `project.json` и запуск генератора. `.cursorignore` больше нет (см. 013).
- **Статус:** действует

## 013 — 2026-09-20 — Агент — Claude Code, Cursor остаётся IDE

- **Решение:** правила, скиллы, хуки, разрешения агента — `CLAUDE.md`, `.claude/`, `.mcp.json`. `.vscode/` (SFTP, сниппеты, Live Sass, расширения) остаётся для ручной работы в Cursor. `.cursor/` и `.cursorignore` удалены.

- **Следствие:** границы агента — `permissions` и хуки, не `.cursorignore`. Правила редактора (табы, сниппеты) — в `.editorconfig` и `.vscode/`.

## 012 — 2026-09-20 — Заливка агентом: `guarded-auto` по умолчанию (заменяет 005)

- **Решение:** режим в `ACCESS.md` → «Заливка»: `guarded-auto` (хук заливает каждую правку с проверкой и откатом), `stage-auto` (то же на stage), `manual` (как в 005: по команде или «да»). `uploadOnSave` в Cursor не трогаем — это ручная работа.
- **Причина:** сайты живые, локальной копии нет, правку можно проверить в браузере только на сервере; заливка «по команде» ломала цикл проверки. Защита — `php -l`, бэкап, проверка сайта и лога, откат.
- **Следствие:** правка идёт на прод сразу; вёрстка, ломающая не PHP, видна посетителям, пока агент проверяет (критичные сайты — `stage-auto`). Файл, которого нет на сервере, при откате удаляется.
- **Статус:** действует

## 011 — 2026-09-03 — `__inner` и `alignfull` вместо своих дублей

- **Решение:** если у блока обязательны `__inner` / `__inner-container` и `alignfull` — вешаем наши 90%/1200px и full-parent на эти классы. Свои `{stem}-container` и `--full` не добавляем рядом.
- **Причина:** вторая обёртка ломает InnerBlocks и валидацию Gutenberg; ядро уже даёт inner и выравнивание.
- **Следствие:** `section-shell` стилизует `&__inner` и `.alignfull`. `{stem}-container` — только где inner нет. Стили ядра у `.alignfull` переопределяем специфичностью, не `!important`.
- **Статус:** действует

## 010 — 2026-09-03 — Каркас секции и контейнера

- **Решение:** контент одной ширины: секция на 100% (сброс margin/padding, `padding-block` через fluid при двух значениях), внутри `{stem}-container` (90% / max-width 1200px). Семантика HTML без дубля `header`/`footer` ядра. Layout — flex/grid и `gap`. Rules `markup-layout`, `scss-bem`.
- **Причина:** иначе каждая секция задаёт свою ширину; `supports.spacing` не даёт одну колонку и fluid `padding-block`. От фиксированного «всегда fluid-fs» отказались: миксин только если в макете два значения (уточнено 040: заголовки — всегда, остальное — разница больше 3 px).
- **Следствие:** ширину колонки не вешать на секцию. Gutenberg: колонка на `__inner`, полная ширина на `alignfull` (№011). Иначе `{stem}-container`. Именованные брейкпоинты раньше сырых `up()`/`down()`. `!important` только если специфичность не достаёт.
- **Статус:** действует

## 009 — 2026-09-02 — Папка на каждый пакет, внутри фронт и бэк

- **Решение:** у каждой своей темы и каждого своего плагина — своя папка `{slug}/`, внутри слои `front/` и `back/` если они есть. Пакетов может быть несколько.
- **Причина:** в проекте сразу несколько тем или плагинов; плоский `theme/front` смешивает пакеты. Слой нужен, чтобы не тянуть витрину вместе с PHP.
- **Следствие:** `project-base/themes/<slug>/{front,back}/` и `project-base/plugins/<slug>/{front,back}/`. Корневой INDEX — таблица пакетов. Чужой parent без папки. Пустой слой не заводить.
- **Статус:** действует

## 008 — 2026-09-02 — Чтение кода через Read / Grep / Glob

- **Решение:** исходники открывать встроенными Read, Grep, Glob. Навигация INDEX → детальный md → файл. Карту символов собирать Grep'ом, не скриптом. Rule `read-code`.

- **Следствие:** нельзя писать AST/php-parser, разовые обходчики, JSON-индексы исходников и запускать `wordpress-router` «чтобы понять проект». `project-ops` не трогает.

## 007 — 2026-09-02 — Figma при старте и через MCP

- **Решение:** макет Figma спрашивается в блоке F3 `project-init/access.md` и пишется в ACCESS.md. MCP — remote `https://mcp.figma.com/mcp` в `.mcp.json`; вход — OAuth (Connect), не PAT. Без MCP агент не угадывает макет.

## 006 — 2026-09-02 — WP-CLI и браузер при старте проекта

## 005 — 2026-09-02 — Заливка агентом только при SSH и с согласия

- **Решение:** если SSH есть, агент сам обновляет файлы на сервере (`sftp-sync upload`). Без команды («залей» и т.п.) и без «да» — не заливает. Нет SSH — агент сервер не трогает, человек сохраняет в редакторе (`uploadOnSave`).
- **Причина:** иначе каждая правка сразу уезжает на живой сайт; пользователь должен решать, когда сервер обновлять.
- **Следствие:** compile/build остаются локальными до согласия. WP-CLI по SSH — тоже по команде или «да».
- **Статус:** отменено, заменено 012

## 004 — 2026-09-02 — Память доступов в ACCESS.md

- **Решение:** любой доступ, который пользователь дал агенту (SSH, SFTP, WP-CLI, админка), сразу пишется в `ACCESS.md` и в `.vscode/ssh.json` / `sftp.json`. Перед вопросом агент читает ACCESS.md. Пароль в чат не повторять.
- **Причина:** иначе каждый чат заново спрашивает хост и логин, хотя они уже были.
- **Следствие:** интерактивный `ssh` запрещён (агент — `ssh-exec.mjs`). Пустой host в ssh.json наследует SFTP. В ACCESS.md пароль не дублировать, если он уже в json.
- **Статус:** действует

## 003 — 2026-09-02 — Канон операций в skill `project-ops`

- **Решение:** SFTP/FTP, компиляция SCSS и сборка блоков — только skill `project-ops` (разделы + скрипты). Агент не подбирает WinSCP/lftp/scp и не пишет CSS руками. Человек в редакторе по-прежнему Live Sass и расширение SFTP.

- **Следствие:** пароль скрипт читает сам и в чат не попадает; FTP-конфиг агент не открывает. `sync-up` всего whitelist — только по явной просьбе.
- **Статус:** действует
