## 066 — 2026-11-20 — Языки: общение по настройкам, проект — по профилю

- **Решение:** с пользователем агент говорит на языке из настроек Claude Code (`language`), не задан — на языке сообщений пользователя; язык вывода инструментов, скиллов и логов — не повод переключаться.
  Для проекта — три поля `project-base/INDEX.md` → «Языки работы»: **Документация** (`project-base/`), **Комментарии в коде** (своя тема, плагины, `markup/`), **Коммиты** (новые сообщения);
  варианты — английский, украинский, русский или свой. Спрашивает `project-init` на этапе 2 (`brief.md` → «Языки работы»), существующему сайту — с подсказкой по коду и истории.
  Прочерк — спросить один раз и записать. Старые комментарии на другом языке — переводятся в той функции или блоке, которые агент правит; весь код — по просьбе. Прошлые коммиты не переписываются.
  Имена в коде и строки `__()` — всегда по-английски. Сам шаблон (правила, скиллы, решения, тексты хуков и скриптов) — по-русски.
- **Причина:** шаблон открыт, а `CLAUDE.md` требовал «всё по-русски» и `.claude/settings.json` задавал `language: russian` — любой, кто возьмёт шаблон, получил бы русскоязычного агента;
  зарубежным клиентам нужны комментарии и документы на их языке, при этом с пользователем удобно говорить на своём. Одно поле на всё отброшено: документы читает пользователь, код — клиент и другие разработчики.
- **Следствие:** `CLAUDE.md` → «Язык» и «Код», правила `code-style`, `project-structure`, скиллы `project-init` (`SKILL.md`, `brief.md`), `project-structure`, `project-ops`, заготовки `project-base/INDEX.md`, `themes/_README.md`, `plugins/_README.md`;
  миграция 2026.11.20.2 — поля в профиль действующих проектов (по умолчанию — русский, как было). `language` в `.claude/settings.json` шаблона убирает человек (019); свой язык пользователь задаёт в настройках Claude Code на своей машине.
- **Статус:** действует

## 065 — 2026-11-20 — Открытый шаблон под MIT

- **Решение:** репозиторий шаблона открыт (`https://github.com/andrei-porsev/wordpress-template`, адрес — `manifest.json` → `repo`); свой код и документы — MIT (`LICENSE` в корне).
  Сторонние скиллы в шаблоне не хранятся (016) — остаются под лицензиями своих источников (`skills.json` → `sources` → `license`), таблица источников и лицензий — `THIRD-PARTY-NOTICES.md`.
  `README.md` (по-английски — для заказчиков), `.github/workflows/tests.yml` — selftest хуков, тесты `project-ops`, `decisions-check --strict` на Windows.
  `LICENSE`, `README.md`, `THIRD-PARTY-NOTICES.md`, `.github/` в проекты не попадают (манифест → `exclude`): код сайта клиента — по договору с клиентом.
  `session-check` анонимным `git ls-remote` проверяет, не открыт ли GitHub-репозиторий проекта (в нём доступы), — 🔴 первой строкой.
  История шаблона переписана без имён сайтов и клиентов; подключённые проекты переводятся на новые хеши `template-update.mjs --remap` (`project-ops` → `template.md`).
- **Причина:** шаблон — витрина работы для заказчиков (Upwork): виден код и регулярные коммиты. MIT — самая простая и привычная заказчикам лицензия: использовать и менять можно, с сохранением авторства, без гарантий.
  GPL-3.0 отброшена — строже для тех, кто берёт шаблон себе; «без лицензии» — шаблон никто не может применить.
  Переписывание истории сохраняет число и даты коммитов, а старые хеши в метках проектов чинит `--remap`.
  Шаблон чужие файлы не распространяет — тексты чужих лицензий рядом с копиями не нужны; у скиллов Figma открытой лицензии нет (Figma Developer Terms).
  Адрес по `https` — шаблон доступен без SSH-ключа владельца. Открытый шаблон рядом с приватными проектами — риск, что проект по ошибке сделают публичным вместе с паролями.
- **Следствие:** в журналах, коммитах и примерах шаблона — без имён клиентов, доменов своего stage и путей своей машины; примеры — `acme`, `<домен stage>`.
  Репозиторий проекта на шаблоне — только приватный (002): в нём доступы.
- **Изменено:** 2026-11-20 — сторонние скиллы больше не лежат в шаблоне (016): `THIRD-PARTY-NOTICES.md` — только таблица источников и лицензий, без копий текстов.
- **Статус:** действует

## 043 — 2026-10-19 — Единицы: rem, em, px

- **Решение:** кегли и отступы (`padding-block`, `gap`, поля компонентов) — rem; в коде числа из макета в px, переводят `to-rem()` и `fluid` / `fluid-fs` (база `$cltm-rem-base: 16`). `fluid` на выходе — `clamp(<min>rem, <смещение>rem ± <наклон>vw, <max>rem)`. em — то, что привязано к своему тексту (поля и иконка кнопки, `letter-spacing`, отступы элементов контента); `line-height` — без единиц; px — рамки, `outline`, тени, радиусы, мелкие детали, `max-width` контейнера, брейкпоинты, значения из полей редактора (`fluid-var`). - **Следствие:** `_starter/scss/abstracts/_mixin.scss` — `to-rem()` и `fluid` (убывающая пара, одинаковые значения, `!important`, `$unit: px`). Функция названа `to-rem`, а не `rem`: у CSS есть своя `rem()`. Проекты, уже скопировавшие `abstracts/`, не меняются — при переходе копировать `_mixin.scss` и `_variables.scss` заново. `scss-bem` → «Единицы», `blocks`, README заготовки, паспорт дизайна.
