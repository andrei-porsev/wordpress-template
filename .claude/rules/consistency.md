# Единообразие и актуальность (решение 059)

## Типы контента

Как оформляется запись каждого типа (пост, проект, услуга, товар) — `project-base/content-types.md` (заготовка `project-base/_starter/content-types.md`).

- **Оформили первую запись типа** или поменяли оформление типа — сразу раздел в `content-types.md`: образец, шаблон, структура сверху вниз, поля, «не делать».
  Показать пользователю, после «да» — «Утверждено», коммит. Файла нет — завести из заготовки.
- **Добавляешь или правишь запись** этого типа — сначала прочитать раздел и делать по нему; в конце сверить с образцом (порядок блоков, поля, картинки).
  Раздела нет — сначала собрать его по образцу, который назовёт пользователь, или по уже оформленной записи.
- Структуру, где можно, закрепить в коде: паттерн, `template` у CPT, шаблон `single-<тип>` — по просьбе или в плане правки, не молча.
- Старые записи, оформленные иначе, — списком в «Расхождения», переделка — по просьбе.

## Один источник — правка везде

Меняешь значение, текст или фрагмент (телефон, адрес, почта, цена, ссылка, подпись, кусок разметки, размер, правило) — до «готово» найти все его копии:

- **Код и документы** — Grep старого значения по своим темам и плагинам, `markup/`, `project-base/` (паспорт, `content-types.md`, карта, `INDEX.md`).
- **Контент сайта** — поиск по базе на сервере (WP-CLI, только чтение: `wp db search`, `wp post list --s=`); правка записей и опций — только списком и после «да» (правило `safety`).
- **Шаблон** — при правке правил шаблона: Grep по `.claude/`, `CLAUDE.md`, `project-base/WORKFLOW.md`.

В отчёте — «обновлено N мест» и что намеренно оставлено. Значение повторяется в двух и более местах кода — предложить один источник
(токен, опция, `template-part`, synced pattern, константа), не переделывать молча. Компоненты вёрстки — решение 056 (`site-design`, `layout-check`).

## Снимок — перепроверить перед действием

Строки хуков при старте, память, отчёты других сессий и прочитанное раньше — снимок на тот момент. Другой чат мог уже обновить шаблон, скиллы, ветку, сервер.
Перед тем как предлагать или делать действие над общим состоянием (обновление скиллов или шаблона, миграция, заливка, выкатка, смена ветки, правка записи) —
перечитать источник: файл (`.claude/template.json`, `skills.json`, `ACCESS.md`), `git status` / `git branch` / `git log -3`, сервер — `sftp-sync.mjs compare`.
Уже сделано — сказать одной строкой и не предлагать.

Обновление проекта до версии шаблона агент не предлагает — только по просьбе пользователя (`project-ops` → `template.md`).
