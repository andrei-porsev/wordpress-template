## Кто обновляет сервер

Человек сохранил в редакторе — `uploadOnSave` (ручная работа в Cursor), агент не дублирует.

Правки агента — по режиму `ACCESS.md` → «Заливка» (решение 012):

- `guarded-auto` (по умолчанию) и `stage-auto`: заливает хук после каждой правки в своей теме/плагине; сам `upload` не вызывать. Ошибку хука (откат) — исправить и править снова.
- `manual`: заливать только по команде («залей», «выложи», «задеплой») или после «да», список путей короткий.
- Нет SSH/SFTP (host пустой) — заливки нет, режим фактически `manual`.

После заливки правку проверь в браузере.

Собранный CSS и `build/` создаёт Bash (compile / `npm run build`), хук их не видит: после сборки залей результат сам — `sftp-sync.mjs upload <пути>` (при `stage-auto` с флагом `--stage`; в `manual` — по команде или после «да»).

## Доступы

Сначала `ACCESS.md` (SSH, WP-CLI, URL сайта, админка, браузер, Figma). Заполнено или «нет» — не спрашивать снова.
При «старт проекта» поля собирает `project-init` → `access.md`, не откладывать.
Новый доступ от пользователя — в том же ходе в `ACCESS.md` и `ssh.json` / `sftp.json`. Пароль в чат не цитировать.

Прочие команды — `INDEX.md` → «Команды».
