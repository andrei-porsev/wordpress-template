# Разметка секций

Стили — rule `scss-bem`. Префикс `{stem}` — из `CLAUDE.md` и `project-base/project.json` (в заготовке SCSS — `cltm`, заменить).

## Семантика и SEO

- Семантический тег по роли: сайт — один `<header>` и один `<footer>`; контентные блоки — `<section>` / `<article>` / `<nav>`.
- Gutenberg / FSE / `template-part` уже дал `<header>` или `<footer>` — свою секцию этим тегом **не** оборачивать.
- Один `<h1>` на страницу. Заголовок секции — следующий уровень (`h2`…), не пропускать уровни.
- Лишних обёрток нет: нет «своего header вокруг header ядра».

## Каркас

Секция всегда на всю ширину. Узкая колонка — внутренний контейнер. Остальной контент — **внутри** него.

```html
<section class="cltm-hero alignfull">
	<div class="cltm-hero__inner">
		<h2 class="cltm-hero__title">…</h2>
		<div class="cltm-hero__grid">…</div>
	</div>
</section>
```

- Секция: `{stem}-header`, `{stem}-hero`, `{stem}-cta`… Тег — по семантике, не по привычке.
- Контейнер: если у блока обязателен `__inner` / `__inner-container` (InnerBlocks, Cover, Group) — колонка вешается **на этот класс**, вторую обёртку `{stem}-container` не добавлять. Нет обязательного inner — `{stem}-container`.
- На всю ширину родителя: если у блока обязателен `alignfull` — привязка к `.alignfull`, стили ядра (`100vw`, отрицательные margin) **переопределяем** своими (`width: 100%`, `max-width: none`, `margin-inline: 0`). Свой `--full` рядом не плодить.
- InnerBlocks / ACF / `template-parts` рендерятся внутрь контейнера.

## Вёрстка макета (`markup/`)

Статичная вёрстка для показа клиенту (`project.json` → `markup: true`) — **свой код наравне с темой: все требования шаблона действуют так же**, без упрощений «это же только макет»:

- **Код:** `code-style` (префикс `{stem}`, комментарии), только Edit / Write (решение 048), разовые скрипты не пишут в `markup/`.
- **Разметка:** этот файл целиком — семантика, каркас секции (`alignfull` + `__inner`), «Минимум разметки»; скилл `semantic-html`.
- **Стили:** `scss-bem` — БЭМ, миксины брейкпоинтов, `fluid*` (040, 049), единицы (043), цвета (047), медиазапросы внутри селектора; SCSS — заготовка `_starter`, общий с темой; скилл `good-css` с исключениями `scss-bem`.
  Токены — CSS-переменные с именами пресетов WordPress (`--wp--preset--color--<slug>`, `--wp--preset--font-size--<slug>`, `--wp--preset--spacing--<slug>`) в `markup/assets/scss/` — те же слаги, что пойдут в `theme.json`, чтобы стили переехали без замен.
- **Дизайн:** паспорт `system.md` и `site-design`; шрифты — локальные файлы (`design` → «Шрифты»), картинки — WebP / AVIF / SVG; анимации — правило `motion`, GSAP локальной копией.
- **Проверка:** `layout-check` полностью (ширины, большие экраны, переполнение, клавиатура, разметка секции) по `https://<stage>/markup/…`; `stylelint` — `markup.mjs publish` перед заливкой (хук `markup/` не видит).

Секция вёрстки — будущий паттерн или template-part: те же классы и структура, чтобы посадка переносила разметку, а не переписывала. Шапка и подвал — один раз (общий файл или копия с пометкой источника).
Пути к шрифтам, картинкам и CSS — относительные.

### Сверка компонентов (решение 056)

До посадки вёрстки или экспорта макета на WordPress и при сборке паспорта по готовой вёрстке — один проход по всем страницам, чтобы переносить компоненты, а не разнобой:

1. На каждой странице, 375 и 1440, — сниппет ниже (`browser_evaluate`): заголовки, абзац сразу после заголовка (lead), кнопки. Карточки и прочее — по паспорту или по снимкам.
2. Сгруппировать по роли и виду, в отчёт — таблица «элемент — страницы — классы — значения — предлагаемый токен / компонент».
3. Расхождение в пределах порога — кегль и межстрочный до 2 px, ширина до 40 px — сводится к одному значению общей таблицей, одно «да» на всё.
   Больше порога — вопрос по каждому элементу: это вариант (модификатор) или ошибка.
4. После «да» — один компонент и токены (`scss-bem` → «Структура»), строки в паспорт → «Компоненты» с адресами; новые значения — по `site-design`.

```js
async () => {
	const props = [ 'font-size', 'line-height', 'font-weight', 'max-width' ];
	const pick = ( el, role ) => {
		const s = getComputedStyle( el );
		return { role, cls: el.className, width: Math.round( el.getBoundingClientRect().width ), ...Object.fromEntries( props.map( ( p ) => [ p, s.getPropertyValue( p ) ] ) ) };
	};
	const out = [];
	document.querySelectorAll( 'h1, h2, h3' ).forEach( ( h ) => {
		const tag = h.tagName.toLowerCase();
		out.push( pick( h, tag ) );
		if ( h.nextElementSibling?.matches( 'p' ) ) {
			out.push( pick( h.nextElementSibling, `${ tag } + p` ) );
		}
	} );
	document.querySelectorAll( 'a[class*="btn"], a[class*="button"], button' ).forEach( ( b ) => out.push( pick( b, 'button' ) ) );
	return { page: location.pathname, items: out };
}
```

## Минимум разметки

Выбор элемента — скилл `semantic-html`, CSS вместо обёрток — `good-css` (с исключениями из `scss-bem` → «Скиллы вёрстки»).
Каждый элемент — с ролью: семантика (заголовок, список, ссылка, `section`), раскладка (контейнер `grid` / `flex`) или стиль, который нельзя повесить на существующий элемент. Нет роли — элемента нет.

- Без обёрток ради одного свойства: отступ — `gap` / `padding` родителя, фон и рамка — на самом элементе, выравнивание — свойствами родительского `grid` / `flex`.
- Декор — `::before` / `::after`, `background`; пустые `div` / `span` под декор не заводить.
- Текст без `span` на кусках; нужны (анимация по словам) — `aria-label` с целой фразой на родителе, куски `aria-hidden`, пробелы между кусками в разметке (иначе текст склеивается для поиска и экранных чтецов).
- FSE и паттерны: нет Group внутри Group без своей роли — один блок с нужным `layout` (Row, Stack, Grid); Spacer — не вместо отступов секции; карточка в карточке — нет.

## Админка

Дефолты контейнера — переменные темы (`$cltm-container-width` 90%, `$cltm-container-max-width` 1200px). Инспектор блока может переопределить CSS-переменными на обёртке секции (`--cltm-container-width`, `--cltm-container-max-width`, пара `--cltm-pad-min` / `--cltm-pad-max` для `padding-block`). Поля заводим, только если редактору это нужно; иначе — дефолт темы.
