# Проверка вёрстки после правки

Задача с шаблоном или стилями не «готово», пока правка не проверена в браузере (Playwright) по URL из `ACCESS.md`.

## Брейкпоинты

1. **`INDEX.md` → «Профиль проекта» → «Брейкпоинты темы»** — найдены при инициализации (SCSS, CSS темы и плагинов вёрстки, билдер, фреймворк; `project-init` → `site.md`).
   Заполнено — проверяем по ним: каждый с обеих сторон (768 → 767 и 768) + 375, 1440, 1920; значения ближе 20 px объединять. Таблица ниже — тогда не нужна.
2. Иначе — `_breakpoints.scss` проекта (`assets/scss/abstracts/` темы или плагина); нет копии или значения не менялись — заготовка `project-base/_starter/scss/abstracts/_breakpoints.scss`.

Значения заготовки (миксин → диапазон, px):

| Миксин | От | До |
|--------|----|----|
| `mobileSmall` | 0 | 374.98 |
| `mobile` | 375 | 479.98 |
| `mobileMedium` | 480 | 767.98 |

## Проверка по ширинам

Объём проверки зависит от правки:

- **Каркас — полный набор.** Правка `header`, `footer`, каркаса секций (`__inner`, `alignfull`, контейнер), `_layout`, `_breakpoints`, глобальных стилей, шаблона страницы целиком, а также итоговая проверка перед «готово» по новой странице или шаблону.
- **Локальная правка — только затронутые диапазоны.** Один блок, компонент, секция: проверяем диапазоны, чьи миксины (`tablet`, `laptopDown`…) или `$bp-*` есть в изменённых файлах, плюс соседние с ними. Правка без медиазапросов (базовые mobile-first стили) затрагивает все диапазоны от базового и выше — тогда тоже полный набор.

1. **Контрольные ширины — нижние границы диапазонов:** 320 (самый узкий в `mobileSmall`), 375, 480, 768, 992, 1024, 1200, 1440. Полный набор — все; для локальной правки — только затронутые и соседние.
   На каждой: `browser_resize` (высота 900) и `browser_evaluate` с проверкой переполнения (ниже). Скриншоты здесь не нужны.
2. **Границы переключения** — на 1px меньше нижней границы (767, 991, 1023, 1199, 1439, а также 479 и 374) — только для диапазонов, чьи миксины или `$bp-*` встречаются в изменённых файлах: там ломается переключение.
3. **Скриншоты:** при полном наборе — мобильный (375), планшетный (768), десктопный (1440) и нижняя граница каждого затронутого диапазона; при локальной правке — только нижняя граница затронутых диапазонов. Всего не больше 6 файлов на задачу.
4. Расхождение в любой ширине — исправить и повторить проверку этой и соседних ширин, а не только последней.

Проверка переполнения (`browser_evaluate`), результат должен быть `overflow: false`, `bad: []`:

```js
() => {
	const w = document.documentElement.clientWidth;
	const bad = [ ...document.querySelectorAll( 'body *' ) ]
		.filter( ( e ) => {
			const r = e.getBoundingClientRect();
			return r.width > 0 && r.right > w + 1;
		} )
		.slice( 0, 5 )
		.map( ( e ) => `${ e.tagName.toLowerCase() }.${ String( e.className ).trim().replace( /\s+/g, '.' ) } → ${ Math.round( e.getBoundingClientRect().right ) }px` );
	return { width: w, scrollWidth: document.documentElement.scrollWidth, overflow: document.documentElement.scrollWidth > w, bad };
}
```

## Что отдаёт сайт

Итог — по тому, что сайт отдаёт посетителю после заливки и сброса кеша (`project-ops` → `cache.md`). Подставленный в страницу свежий CSS — только предварительная проверка вёрстки;
в отчёте тогда «посетители пока не видят: кеш <плагин> не сброшен».
Новое правило дошло — его селектор есть в одном из стилей страницы (`browser_evaluate`, результат — адрес стиля, не `null`):

```js
async () => {
	const sel = '.acme-to-top'; // селектор из правки
	for ( const l of document.querySelectorAll( 'link[rel="stylesheet"]' ) ) {
		const css = await ( await fetch( l.href, { cache: 'no-store' } ) ).text();
		if ( css.includes( sel ) ) {
			return l.href;
		}
	}
	return [ ...document.querySelectorAll( 'style' ) ].some( ( s ) => s.textContent.includes( sel ) ) ? 'inline <style>' : null;
}
```

`null` после сброса — смотреть, подключён ли стиль и не отдаёт ли кеш старую страницу (перезагрузка с `?nocache=<время>`). JS — так же по `script[src]`.

## Остальное

- **Консоль и сеть:** нет ошибок в консоли, нет 4xx/5xx на ресурсах сайта.
- **Семантика:** одна `h1`, заголовки без пропуска уровней, у `img` есть `alt`, у ссылок и кнопок понятный текст.
- **Макет:** есть Figma или Claude Design в `ACCESS.md` — сверить по ширинам макета, расхождения перечислить списком.
- **Анимации:** есть GSAP — дополнительные пункты правила `motion` (переполнение в начальном состоянии, `prefers-reduced-motion`).
- **Стиль кода:** отчёт `phpcs` / `stylelint` из хука post-edit — исправить ошибки. `stylelint-disable` и `phpcs:ignore` — только с причиной, не по умолчанию.

Скриншоты в `project-base/screenshots/<задача>/` кладём только при редизайне или по просьбе: JPEG или сжатый PNG.
Есть `project-base/screenshots/before/` (снято при инициализации) — после правки каркаса сравнить те же страницы и ширины: поехало на странице, которую не трогали, — назвать.
Итог — короткий отчёт по ширинам: что проверено, где переполнение и что не совпало с макетом. Сломалась страница целиком (5xx) — это откат хука, см. `safety`.
