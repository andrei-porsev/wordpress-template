# Проверка вёрстки после правки

Задача с шаблоном или стилями не «готово», пока правка не проверена в браузере (Playwright) по URL из `ACCESS.md`.

## Брейкпоинты

1. **`INDEX.md` → «Профиль проекта» → «Брейкпоинты темы»** — найдены при инициализации (SCSS, CSS темы и плагинов вёрстки, билдер, фреймворк; `project-init` → `site.md`).
   Заполнено — проверяем по ним: каждый с обеих сторон (768 → 767 и 768) + 375, 1440, 1920; значения ближе 20 px объединять. Таблица ниже — тогда не нужна.
2. Иначе — `_breakpoints.scss` проекта (`assets/scss/abstracts/` темы или плагина); нет копии или значения не менялись — заготовка `project-base/_starter/scss/abstracts/_breakpoints.scss`.

## Проверка по ширинам

Объём проверки зависит от правки:

- **Каркас — полный набор.** Правка `header`, `footer`, каркаса секций (`__inner`, `alignfull`, контейнер), `_layout`, `_breakpoints`, глобальных стилей, шаблона страницы целиком, а также итоговая проверка перед «готово» по новой странице или шаблону.
- **Локальная правка — только затронутые диапазоны.** Один блок, компонент, секция: проверяем диапазоны, чьи миксины (`tablet`, `laptopDown`…) или `$bp-*` есть в изменённых файлах, плюс соседние с ними. Правка без медиазапросов (базовые mobile-first стили) затрагивает все диапазоны от базового и выше — тогда тоже полный набор.

1. **Контрольные ширины — нижние границы диапазонов:** 320 (самый узкий в `mobileSmall`), 375, 480, 768, 992, 1024, 1200, 1440. Полный набор — все; для локальной правки — только затронутые и соседние.
   На каждой: `browser_resize` (высота 900) и `browser_evaluate` с проверкой переполнения (ниже). Скриншоты здесь не нужны.
2. **Границы переключения** — на 1px меньше нижней границы (767, 991, 1023, 1199, 1439, а также 479 и 374) — только для диапазонов, чьи миксины или `$bp-*` встречаются в изменённых файлах: там ломается переключение.
3. **Скриншоты:** при полном наборе — мобильный (375), планшетный (768), десктопный (1440) и нижняя граница каждого затронутого диапазона; при локальной правке — только нижняя граница затронутых диапазонов. Всего не больше 6 файлов на задачу; пары «было → стало» — до 12 (6 пар), картинки-разницы не в счёт.
4. Расхождение в любой ширине — исправить и повторить проверку этой и соседних ширин, а не только последней.

Проверка переполнения (`browser_evaluate`), результат должен быть `overflow: false`, `bad: []`:

```js
() => {
	const w = document.documentElement.clientWidth;
	const bad = [ ...document.querySelectorAll( 'body *' ) ]
		.filter( ( e ) => {
			const r = e.getBoundingClientRect();
			return r.width > 0 && r.right > w + 1;
		} )
		.slice( 0, 5 )
		.map( ( e ) => `${ e.tagName.toLowerCase() }.${ String( e.className ).trim().replace( /\s+/g, '.' ) } → ${ Math.round( e.getBoundingClientRect().right ) }px` );
	return { width: w, scrollWidth: document.documentElement.scrollWidth, overflow: document.documentElement.scrollWidth > w, bad };
}
```

## Окружение браузера

Проверка — Playwright MCP (`ACCESS.md` → «MCP браузера»). Встроенная панель приложения, пока скрыта, — страница без кадров: `requestAnimationFrame` не вызывается,
переходы и плавная прокрутка стоят, каждый скриншот отрисовывает один кадр; ширина свёрнутой панели — 0. Это не ошибка вёрстки (решение 039).

1. **Размер — явно** до первого замера (`browser_resize`, высота 900) и сверка `innerWidth`; 0 или не тот — повторить, не мерить.
2. **Состояние после действия** (прокрутка, клик, открытие меню) — ожиданием с проверкой кадров (`browser_evaluate`). Проверять класс состояния и конечное значение, не промежуточную `opacity`:

```js
async () => {
	const done = () => document.querySelector( '.acme-to-top' )?.classList.contains( 'is-visible' ); // условие из правки
	let frames = 0;
	const t = performance.now();
	await new Promise( ( r ) => {
		const f = () => ( ++frames, performance.now() - t < 500 ? requestAnimationFrame( f ) : r() );
		requestAnimationFrame( f );
		setTimeout( r, 600 );
	} );
	const t0 = performance.now();
	while ( frames > 5 && ! done() && performance.now() - t0 < 3000 ) {
		await new Promise( ( r ) => setTimeout( r, 100 ) );
	}
	return { ok: Boolean( done() ), frames, ms: Math.round( performance.now() - t0 ) };
}
```

   `frames` ≤ 5 — кадров нет, `ok` не в счёт: перейти в Playwright или показать панель; на крайний случай — скриншот (масштаб 0.1) и проверка, до 5 раз.
3. **Анимации:** основной прогон — с `prefers-reduced-motion: reduce` (Playwright `browser_emulate_media`): переходы мгновенные и проверена ветка reduced-motion (правило `motion`).
   Анимированную ветку — одним замером из п. 2, без скриншотов промежуточных кадров.
4. **Сначала окружение.** Результат расходится между вызовами без правки кода — повторить по п. 2. Не подтвердилось — это не ошибка и не попытка в счёт лимита из трёх (`safety`); код править только после повторяемого результата.

## Что отдаёт сайт

Итог — по тому, что сайт отдаёт посетителю после заливки и сброса кеша (`project-ops` → `cache.md`). Подставленный в страницу свежий CSS — только предварительная проверка вёрстки;
в отчёте тогда «посетители пока не видят: кеш <плагин> не сброшен».
Новое правило дошло — его селектор есть в одном из стилей страницы (`browser_evaluate`, результат — адрес стиля, не `null`):

```js
async () => {
	const sel = '.acme-to-top'; // селектор из правки
	for ( const l of document.querySelectorAll( 'link[rel="stylesheet"]' ) ) {
		const css = await ( await fetch( l.href, { cache: 'no-store' } ) ).text();
		if ( css.includes( sel ) ) {
			return l.href;
		}
	}
	return [ ...document.querySelectorAll( 'style' ) ].some( ( s ) => s.textContent.includes( sel ) ) ? 'inline <style>' : null;
}
```

`null` после сброса — смотреть, подключён ли стиль и не отдаёт ли кеш старую страницу (перезагрузка с `?nocache=<время>`). JS — так же по `script[src]`.

## Редактор и вставка без сохранения (решение 050)

- **Вход в админку — пользователь агента** (`ACCESS.md` → «Пользователь агента»). Пароль агент вводит только на локальном сайте и на stage, который назвал пользователь;
  на проде — нет (ограничение Claude, не шаблона). Нет сессии на проде — попросить: «Войдите под `claude-agent` в браузере проверки (пароль — `ACCESS.md`), скажите „готово“»,
  и ждать. Встроенная панель хранит вход между сессиями; Playwright `--isolated` — до перезапуска браузера. Сессия истекла — та же просьба, проверку не пропускать.
- Блок, паттерн, настройки в сайдбаре — проверка в редакторе: вставка из своей категории, превью, смена настроек; не сохранять. Лучше на stage.
- Вход не дали или нет пользователя агента — первая строка отчёта «Залито, в редакторе не проверено: <причина>», без «готово».
- **Вставка разметки в DOM** (динамический блок, `do_blocks` через WP-CLI) — допустима для вида и ширин, если CSS элемента есть на странице без него:
  селектор находится в стилях страницы (проверка из «Что отдаёт сайт»). Стиль подключается только при блоке (`block.json` → `style`, `wp_enqueue_block_style`) —
  вставка покажет элемент без стилей: проверять на черновике (`wp post create --post_status=draft`, решение 035) и удалить его после проверки.
- **Клавиатура** у интерактивного элемента: Tab доходит до каждой ссылки и кнопки по порядку, `:focus-visible` виден на обоих фонах, Enter срабатывает.
  Фокус — `browser_press_key` Tab и `document.activeElement`; итог — строкой в отчёт.

## Было → стало (решение 046)

Пара снимков — для заметной правки (решение 044) и правки каркаса; мелкой — не нужна. Пары — `.claude/.state/reports/shots/<задача>/` (не в git;
старше 180 дней удаляются сами, раньше — `shot-diff.mjs clean <задача>` / `--all` по просьбе пользователя).

1. **«Было» — до первой правки** (при `guarded-auto` прод меняется сразу); при коротком `manual` — до `deploy`. Те же адрес и ширины для «стало»:
   375, 1440 и нижняя граница затронутого диапазона. Компонент — снимок элемента, каркас — страница целиком (главная + 1–2 типовые).
2. **Подготовка перед каждым снимком** — и «было», и «стало» (браузер выгружает картинки между снимками): Playwright, `browser_emulate_media` → `reducedMotion: reduce`,
   затем `browser_evaluate` ниже; `pending` — 0. `browser_take_screenshot` с `filename: .claude/.state/reports/shots/<задача>/before-1440.png` (`after-…`).
3. **Сравнение:** `node .claude/skills/project-ops/scripts/shot-diff.mjs diff <было> <стало>` — доля изменённого, области (x, y, размер), картинка-разница `…-diff.png`.
   Область вне затронутого элемента — регрессия: разобрать до «готово». «Ширина … несопоставимы» — переснять после подготовки.
   «Одиночные клетки» — шум фото и сглаживания, не правка.
4. **Отчёт:** пары и картинку-разницу показать пользователю файлами + строка итога («изменения только в правом нижнем углу, 0,8%»).

```js
async () => {
	const hide = '.cmplz-cookiebanner, .cmplz-manage-consent'; // «Динамические зоны» из паспорта дизайна
	document.querySelectorAll( 'img[loading="lazy"]' ).forEach( ( i ) => ( i.loading = 'eager' ) );
	for ( let y = 0; y < document.documentElement.scrollHeight; y += innerHeight ) {
		scrollTo( 0, y );
		await new Promise( ( r ) => setTimeout( r, 150 ) );
	}
	scrollTo( 0, 0 );
	await Promise.all( [ ...document.images ].map( ( i ) => ( i.complete ? i.decode().catch( () => {} ) : new Promise( ( r ) => i.addEventListener( 'load', r, { once: true } ) ) ) ) );
	await document.fonts.ready;
	if ( ! document.getElementById( 'shot-mask' ) ) {
		const s = document.createElement( 'style' );
		s.id = 'shot-mask';
		s.textContent = `${ hide } { visibility: hidden !important; } html { scrollbar-width: none; } ::-webkit-scrollbar { display: none; }`;
		document.head.append( s );
	}
	await new Promise( ( r ) => setTimeout( r, 300 ) );
	return { width: document.documentElement.clientWidth, pending: [ ...document.images ].filter( ( i ) => ! i.complete ).length };
}
```

Живое содержимое и плавающие слои (баннер cookies, чат, слайдер, даты, ленты) дают ложную разницу — их селекторы в паспорте дизайна,
«Динамические зоны»; нет паспорта — баннер cookies и чат по умолчанию.
