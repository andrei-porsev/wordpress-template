# QA сайта — `/qa` (решение 062)

Аргументы вызова: `$ARGUMENTS`

QA — отдельная роль: проверяет сайт целиком, независимо от того, кто и как его делал, и **ничего не правит** — только баг-лист.
Исправляет обычная сессия, затем `/qa retest`. Своя правка до «готово» — правило `layout-check`, не этот скилл.

## 0. Перед прогоном

1. **Отдельная сессия.** В этой сессии были правки сайта — предложить запуск в новой (`start_session`, "fresh", бриф: режим, направления, адрес) — иначе агент проверяет «помня, как задумано».
   Пользователь сказал «здесь» — работать здесь, в шапке отчёта «запущено в сессии с правками».
2. **Файл решений** `project-base/qa/QA.md` — прочитать целиком. Нет — создать из `project-base/_starter/qa/QA.md` (раздел «Матрица» — п. 4), показать пользователю.
   Одной строкой до прогона: «Учитываю: N отступлений, M исключений, допуски <…>».
3. **Окружение** — `ACCESS.md`: адрес (stage / прод / локальный), уровень макета (Figma / картинки / нет), браузер (Playwright MCP или `browser.mjs`). Прод — без отправки форм и тестовых заказов (`f-functional.md`).
4. **Матрица страниц** — из `QA.md` → «Матрица». Пусто — собрать: главная, по одной записи каждого типа (`content-types/README.md`, иначе `wp post-type list --public=1` и по одной последней записи),
   архив типа, ключевые (контакты, форма, корзина / оформление, 404, поиск). Записать в `QA.md`, показать списком.

## 1. Что проверять — выбор

Направления — буквы; файл с порядком проверки — `references/`.

| Код | Направление | Файл |
|-----|-------------|------|
| A | Адаптив: ширины, переполнение, обрезка, налезание, зум 200% | `a-responsive.md` |
| B | Браузеры: WebKit (≈ Safari), Firefox | `b-browsers.md` |
| C | Pixel perfect: стили числами против макета + наложение | `c-pixel.md` |
| D | Контент против макета: тексты, заглушки, опечатки | `d-content.md` |
| E | Языки: переводы, длина строк, шрифты, переключатель, `hreflang`, форматы | `e-languages.md` |
| F | Функционал: формы и письма, меню, поиск, 404, ссылки, Woo | `f-functional.md` |
| G | Состояния и крайние случаи: `hover`, `focus`, пустые, длинные, тёмная тема ОС | `g-states.md` |
| H | Доступность, скорость, SEO-база — существующими скиллами | `h-base.md` |
| L | Чек-лист запуска | `l-launch.md` |
| R | Регрессия: снимки до и после | `r-regression.md` |

| Пресет | Состав | Когда |
|--------|--------|-------|
| `handover` | A B C D E G + F кратко (формы, меню, 404) | сдача stage клиенту |
| `launch` | A B C D E F G H L | перед запуском |
| `update` | R + F + консоль и 5xx + A на 375 / 768 / 1440 | после обновлений плагинов, ядра, темы |

Разбор аргументов:

- `/qa handover` — пресет; `/qa handover -B -G` — пресет без B и G; `/qa launch +R` — с добавкой.
- `/qa A C E` — только перечисленные.
- `/qa retest` — перепроверка открытых багов последнего отчёта (п. 4).
- `/qa` без аргументов — `AskUserQuestion`, `multiSelect`: 1) пресет или «свой набор»; 2–3) направления (A–G, H L R) — только при «свой набор»;
  4) объём: все страницы матрицы / только ключевые, языки, браузеры. Затем одной строкой — объём: «N страниц × M ширин × K языков ≈ X проверок», и начать.

Направление невозможно (нет макета для C / D, один язык для E, нет WP-CLI для R-снимков «до» на сервере) — пропустить, в шапке отчёта строкой «C — пропущено: макета нет».
Отступления и исключения из `QA.md` — не баги: такие расхождения в отчёт не заносить.

## 2. Прогон

- Порядок: F и консоль / сеть первыми на ключевых страницах (blocker виден сразу) → A → B → C → D → E → G → H → L. R — по `r-regression.md` (снимки «до» снимаются до обновления).
- Браузер, замеры, подготовка снимков, проверка переполнения — правило `layout-check` («Окружение браузера», «Замеры», «Было → стало»): скрипты оттуда, не копии.
- Каждое расхождение — сразу строкой в отчёт (формат — `references/report.md`), скриншот элемента — `.claude/.state/reports/shots/qa-<дата>-<режим>/<номер>.png`.
- Один и тот же дефект на многих страницах (компонент) — **один** баг со списком адресов, не N багов.
- 3 сбоя окружения подряд (браузер, доступ, MCP Figma) — стоп и вопрос пользователю (правило `safety`); найденное до этого — в отчёт.
- Конец — закрыть браузеры (`browser_close`, `browser.mjs close`, `--browser=…` тоже).

## 3. Отчёт

`project-base/qa/reports/<ГГГГ-ММ-ДД>-<режим>.md` (режим — пресет или `custom`) по `references/report.md`. В ответе пользователю:
итог одной строкой (blocker / major / minor / cosmetic — числа), blocker и major списком со ссылками на строки отчёта, пропущенное и почему.
Версия для клиента — только по просьбе (`report.md` → «Клиенту»).

## 4. Перепроверка — `/qa retest`

Последний отчёт в `project-base/qa/reports/` (или названный). По каждому багу со статусом «открыт» или «исправлен» — повторить его шаг на тех же странице, ширине, браузере, языке:
воспроизводится — «открыт» (дата перепроверки), нет — «подтверждён». Новые дефекты, замеченные попутно, — новыми строками с пометкой «retest».
Итог — в тот же файл (раздел «Перепроверки»), строкой пользователю.

## 5. Решения — `QA.md`

- «Не баг», «так согласовано», «это оставить» от пользователя — статус «не баг» **и в том же ходе** строка в `QA.md` → «Принятые отступления» (что, где, допуск, кем согласовано, дата).
  Без записи «не баг» не ставить: следующий прогон снова найдёт.
- Решение о самом QA (допуск, исключение, браузеры, страницы матрицы, тестовая почта) — в свой раздел `QA.md` и строкой в «Решения»: дата — решение — причина.
- Решение по типу записи («у проектов нет подписей в галерее») — в `content-types/<тип>.md` (правило `consistency`); QA читает файл типа, когда проверяет страницу этого типа.
- Решение сайта, явно отступающее от шаблона («допуск 4 px, отступает от 062»), действует для этого сайта.

## Границы

- Не правит код, контент, настройки; не заливает. Нашёл — записал.
- Формы, заказы, письма — только по `f-functional.md` (stage, тестовые данные). Админка — только смотреть (правило `safety`).
- Решает человек: итоговое «смотрится хорошо», настоящие устройства, приёмка клиентом, письма с прода, качество перевода (QA только помечает сомнительное).
