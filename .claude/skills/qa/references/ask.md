# Опросник — `/qa` без аргументов

Тексты ниже — готовые: показывать как есть, не пересказывать и не сокращать. Буквы — только в скобках в конце подписи (по ним строки отчёта), смысл — словами.
Пресетов в опроснике нет: пресеты — только аргументами (`/qa launch`).

**Внутренние слова в тексты опросника не попадают:** «матрица», «ключевые страницы», «брейкпоинты» без чисел, «пресет», буквы направлений вне скобок.
Страницы — названиями и адресами, ширины — числами в px с указанием, откуда взяты.

## Два вызова `AskUserQuestion`

**Вызов 1 — что проверять.**

1. **До вызова** — убрать недоступные проверки (таблица «Когда не показывать»), причины — первой строкой текста первого вопроса: «Не предлагаю: языки — язык один; pixel perfect — эталона нет».
   Ограничения окружения — там же одной фразой («Прод, stage нет: формы не отправляю, только валидация»).
2. Доступные проверки по порядку таблицы, `multiSelect: true`, по одной галочке на проверку: отмечено — проверять, не отмечено — нет; пункта «не нужно» нет.
   Делить на вопросы по 2–4 галочки поровну: до 4 — один вопрос, 5–8 — два, 9–12 — три. Осталась одна проверка — не спрашивать, сказать строкой.
   `header` — «Проверки», `question` — «Что проверять? Отметьте нужное (1 из N)».

**Вызов 2 — где проверять:** вопросы «Страницы» и «Ширины» (разделы ниже). Ширины не нужны (отмечены только SEO-база, скорость, чек-лист запуска) — только «Страницы».

После ответов — одной строкой словами: «Проверяю: адаптив, Safari и Firefox, функционал — 9 страниц × 12 ширин». Ни одной галочки — спросить словами, что проверить.

## Когда не показывать

| Проверка | Не показывать, если |
|---|---|
| Pixel perfect | нет эталона вида (`c-pixel.md` → «Эталон») |
| Тексты против макета | нет макета (Figma, картинки, PDF); заглушки и опечатки всё равно ищутся в «Функционал» и «Состояния» — сказать строкой |
| Языки | язык один |
| Чек-лист запуска | нет прода (только stage или локальный) — пункты, которые требуют прод, сказать строкой |

## Страницы

`header` — «Страницы», `question` — «Какие страницы проверить? Отметьте группы», `multiSelect: true`.
Источник — `QA.md` → «Матрица» (собрана в `SKILL.md` → п. 4); в опросе — группами, каждая страница названием и адресом.

| Группа (`label`) | `description` — пример |
|---|---|
| Главная и служебные | Главная `/`, Контакты `/contacts/`, Поиск `/?s=тест`, Страница 404 `/404-test/` |
| Магазин — если Woo | Каталог `/shop/`, Категория `/product-category/chairs/`, Товар `/product/oak-chair/`, Корзина, Оформление, Wishlist |
| Записи — по одной каждого типа | Статья блога `/blog/…/`, Проект `/projects/…/`, архивы: Блог `/blog/`, Проекты `/projects/` |
| Остальные страницы | О нас `/about/`, Услуги `/services/`, Политика `/privacy/` |

Групп больше 4 — объединить соседние; страниц в группе много — первые 6 и «ещё N: …» с полным списком в тексте вопроса.

## Ширины

`header` — «Ширины», `question` — «На каких ширинах? Каждое значение — с обеих сторон границы (767 и 768)», `multiSelect: true`.
Источник — `INDEX.md` → «Профиль проекта» → «Брейкпоинты темы», уже по источникам (`project-init` → `site.md` → «Брейкпоинты темы»). Группа без значений — не показывать.

| Группа (`label`) | `description` — пример |
|---|---|
| Тема | Из SCSS / CSS темы или стартера шаблона: 480, 768, 992, 1024, 1200, 1440 |
| Билдер — Elementor | Из настроек сайта Elementor: 767 / 768, 1024 / 1025 |
| Свои прошлого разработчика | В CSS темы и плагинов, не совпадают с темой и билдером: 600 (`style.css`), 860 (`custom.css`) |
| Устройства и большие экраны | 375 (телефон), 1440 (ноутбук), 1920 (монитор), 2560, 3840 |

Значения ближе 20 px объединены (`layout-check` → «Брейкпоинты»). Safari и Firefox — всегда 375 / 768 / 1440, независимо от выбора (`b-browsers.md`), — строкой в тексте вопроса, если отмечены.
