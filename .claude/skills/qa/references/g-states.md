# G — Состояния и крайние случаи

## Состояния элементов

Кнопки, ссылки, карточки, поля форм, пункты меню — на 1440 и 375:

- `hover` — `browser_hover` и вычисленные стили (цвет, фон, подчёркивание, тень) против макета (если в макете есть состояние) или хотя бы заметная разница;
- `focus-visible` — Tab до элемента (`browser_press_key`), рамка видна на обоих фонах (правило `layout-check` → «Клавиатура»);
- `active`, `disabled`, текущий пункт меню, выбранная вкладка, ошибка и успех у поля формы.

Переходы проверять по конечному состоянию (правило `layout-check` → «Замеры», п. 2), не посреди анимации.

## Крайние случаи контента

Найти на сайте, не создавать (создание записей — черновиком и после «да», решение 035):

- самый длинный заголовок записи и карточки (`wp post list --orderby=…` / глазами в архиве), длинное слово без пробелов, длинное имя файла в ссылке;
- запись без изображения записи, без анонса, без рубрики; товар без цены, распроданный;
- пустой архив, поиск без результата, пагинация на последней странице;
- одна карточка в ряду, нечётное число карточек.

Найдено — проверить на 375 и 1440 (скрипты `a-responsive.md`).

## Системные настройки посетителя

- **Тёмная тема ОС** — `browser_emulate_media` `colorScheme: 'dark'`: сайт без тёмной темы не должен частично перекраситься (формы, `color-scheme`), сайт с тёмной темой — по макету.
- **Уменьшение движения** — `reducedMotion: 'reduce'`: анимации отключены или мягкие (правило `motion`).
- **Без JavaScript** — не проверяется (решение 062): WordPress-сайты клиента без JS не используются.

## Серьёзность

Нет видимого фокуса, элемент без hover-обратной связи на десктопе — **minor**. Длинный контент ломает вёрстку — **major**. Частичная перекраска в тёмной теме — **minor**.
