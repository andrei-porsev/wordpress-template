# G — Состояния и крайние случаи

## Состояния элементов

Кнопки, ссылки, карточки, поля форм, пункты меню — на 1440 и 375:

- `hover` — `browser_hover` и вычисленные стили (цвет, фон, подчёркивание, тень) против макета (если в макете есть состояние) или хотя бы заметная разница;
- `focus-visible` — Tab до элемента (`browser_press_key`), рамка видна на обоих фонах (правило `layout-check` → «Клавиатура»);
- `active`, `disabled`, текущий пункт меню, выбранная вкладка, ошибка и успех у поля формы.

Переходы проверять по конечному состоянию (правило `layout-check` → «Замеры», п. 2), не посреди анимации.

## Стресс-тест текста

Вместо поиска длинных записей — длинный текст прямо в DOM открытой страницы, без сохранения: проверяются все карточки, кнопки, меню и заголовки разом.
На каждой странице матрицы, на 375, 768, 1440 (и на границах диапазонов, если выбран полный A). Два режима — по очереди, между ними `browser_navigate` на ту же страницу (страница вернётся как была):

- `repeat` — текст каждого блока × 3 (длинные заголовки, переводы на 20–40 % длиннее);
- `unbroken` — к каждому блоку длинное слово без пробелов (немецкие составные слова, адреса почты, ссылки).

```js
async () => {
	const mode = 'repeat'; // 'repeat' | 'unbroken'
	const word = 'Donaudampfschifffahrtsgesellschaftskapitänsmütze';
	const walk = document.createTreeWalker( document.body, NodeFilter.SHOW_TEXT );
	let n = 0;
	const nodes = [];
	while ( walk.nextNode() ) {
		const t = walk.currentNode;
		if ( t.textContent.trim().length > 1 && ! t.parentElement.closest( 'script, style, noscript, svg, textarea, [contenteditable], .sr-only, .screen-reader-text' ) ) {
			nodes.push( t );
		}
	}
	for ( const t of nodes ) {
		const s = t.textContent.trim();
		t.textContent = mode === 'repeat' ? `${ s } ${ s } ${ s }` : `${ s } ${ word }`;
		n++;
	}
	await new Promise( ( r ) => requestAnimationFrame( () => requestAnimationFrame( r ) ) );
	return { mode, changed: n };
}
```

Сразу после — скрипт «Текст вне своего блока» и переполнение страницы (`a-responsive.md`, п. 2 и 1) и скриншот 375.
Найденное — баг с пометкой «стресс: repeat / unbroken»: на реальном контенте может не проявиться, но сломается на длинном заголовке или переводе.
Обычные решения для исправляющей сессии (в баг не писать): `min-height` вместо `height`, `min-width: 0` у детей flex, `minmax(0, 1fr)` в сетке, `overflow-wrap: anywhere`.

## Крайние случаи контента

Найти на сайте, не создавать (создание записей — черновиком и после «да», решение 035):

- запись без изображения записи, без анонса, без рубрики; товар без цены, распроданный;
- пустой архив, поиск без результата, пагинация на последней странице;
- одна карточка в ряду, нечётное число карточек.

Найдено — проверить на 375 и 1440 (скрипты `a-responsive.md`). Длина текста — стресс-тестом выше, искать длинные записи не нужно.

## Системные настройки посетителя

- **Тёмная тема ОС** — `browser_emulate_media` `colorScheme: 'dark'`: сайт без тёмной темы не должен частично перекраситься (формы, `color-scheme`), сайт с тёмной темой — по макету.
- **Уменьшение движения** — `reducedMotion: 'reduce'`: анимации отключены или мягкие (правило `motion`).
- **Без JavaScript** — не проверяется (решение 062): WordPress-сайты клиента без JS не используются.

## Серьёзность

Нет видимого фокуса, элемент без hover-обратной связи на десктопе — **minor**. Длинный реальный контент ломает вёрстку — **major**; только в стресс-тесте — **minor**
(**major**, если сайт многоязычный и ломается на `repeat`). Частичная перекраска в тёмной теме — **minor**.
