# Тип проекта: маршруты опроса

Первый вопрос `project-init` (шаг 0). От ответа зависят порядок блоков, предзаполнение, что пропускать и какие стеки предлагать.
Блоки A–F — `SKILL.md` → шаг 1, доступы — [`access.md`](access.md). Формат вопросов — `SKILL.md` → «Формат вопроса».

## Вопрос

> **Какой это проект?**
> Зачем: от ответа зависят следующие вопросы, порядок настройки и какие инструменты подключу.

| Вариант | Описание для пользователя |
|---------|---------------------------|
| Новый — нужен дизайн | Сайт с нуля, макета нет: сначала рисуем дизайн, потом верстаем |
| Новый — дизайн есть | Сайт с нуля по готовому макету (Figma, Claude Design или файлы от дизайнера) |
| Клиентский — доработка | Сайт работает, добавляем и правим функции; внешний вид и архитектуру не меняем |
| Клиентский — редизайн | Сайт работает, меняем внешний вид (или тему целиком), сохраняя контент и адреса страниц |

Ответ — в `project-base/INDEX.md` → «Профиль проекта» → «Тип проекта» (`новый: нужен дизайн` / `новый: дизайн есть` / `доработка` / `редизайн: рестайл` / `редизайн: новая тема`).
Повторный запуск `project-init` с заполненным типом — подтвердить одной строкой, не спрашивать заново.

## Новый — общее для обоих вариантов

Кода сайта нет: шаг «анализ кода» пропустить, `sync-down` не нужен.
Варианты различаются только дизайном — разделы ниже; остальное здесь.

**Порядок:** A → B → C → F → D. Блок E — один вопрос «есть ли ограничения от клиента?», без подпунктов.

**Особые вопросы:**

1. **WordPress на хостинге уже стоит?** `да` / `нет, поставите вы` / `сервера ещё нет`
   Зачем: агент не ставит ядро WP; без сервера нет заливки и проверки сайта в браузере.
   - `сервера ещё нет` → блок F0–F2 прочерками, режим заливки `manual`; предложить стек `playground` для локального просмотра.

**Предзаполнение:**

- B. Режим — FSE (рекомендую, лестница п.1); classic / билдер — только если пользователь выберет сам. Тема своя, не дочерняя.
- C. Слаг темы и префикс — предложить из названия проекта (`acme` → тема `acme`, префикс `acme`, text-domain `acme`); подтвердить.
- C. «Куда пишем» — тема; свой плагин только для переносимого функционала.
- F5. Трафика нет → `guarded-auto`.

**Стеки по умолчанию:** `fse` (+ `blocks`); по блоку A — `motion`, `content`; к сдаче — предложить `seo` + `quality`. Стек дизайна — по варианту ниже.

**Дальше:** этапы «Сайт под ключ» — `WORKFLOW.md` → 1.4 (какие этапы — по варианту ниже). SCSS-заготовка — папка `scss/` целиком.

### Новый — нужен дизайн

Вопрос о дизайне в блоке A заменяется этими; объём работ по анимациям, контенту и SEO — как обычно.

1. **Где рисуем дизайн?**
   Зачем: определяет, в каком инструменте агент создаёт макет и откуда потом верстает.
   - `Figma (рекомендую, если нужен файл для клиента или дизайнера)` — агент создаёт файл, дизайн-систему и макеты страниц; нужен платный план Figma с Dev или Full seat → стек `figma`, F3 = `создадим`;
   - `Claude Design` — макет в claude.ai, без Figma → стек `design`, F3b = `создадим`;
   - `без макета` — агент предлагает план: цвета, шрифты, сетку и раскладку страниц; после «да» сразу верстает → стек `design`.
2. **Есть ли референсы?** (сайты, которые нравятся, фирменный стиль, логотип)
   Зачем: дизайн начинается от вкуса клиента, а не с пустого листа. Ответ — в `project-base/design/references.md`.
3. **Какие страницы нужны?** (если контент пишем мы — выяснится на этапе «Структура»; тогда прочерк)
   Зачем: объём макетов и порядок работы.

**Этапы `WORKFLOW.md` → 1.4:** все: бриф → структура → дизайн-система → макеты (или 3–4′) → тексты → тема → сдача. Вёрстка — только по утверждённым макетам.

### Новый — дизайн есть

Вопрос о дизайне в блоке A заменяется этими.

1. **В чём макет?**
   Зачем: откуда агент берёт размеры, цвета и отступы.
   - `Figma` — ссылка на файл, агент читает его через MCP → стек `figma`, F3 = `да`;
   - `Claude Design` — ссылка на дизайн → стек `design`, F3b = `да`;
   - `файлы` (PDF, картинки, XD, Sketch) — положить в `project-base/design/`; размеры агент снимает с картинок приблизительно, лучше попросить Figma → стек `design`.
2. **Все ли страницы нарисованы?** `все` / `ключевые, остальные по аналогии` / `не знаю`
   Зачем: недостающие страницы агент собирает из готовых блоков макета, не придумывая новый стиль.
3. **Какие ширины в макете?** (например 375 / 768 / 1440)
   Зачем: под эти экраны агент проверяет вёрстку; недостающие ширины — адаптив по своему усмотрению.
4. **Есть ли в макете UI-kit?** (страница с цветами, шрифтами, кнопками) `да` / `нет`
   Зачем: при «да» агент переносит его в `theme.json` один раз; при «нет» — собирает из макетов и показывает на утверждение.

**Этапы `WORKFLOW.md` → 1.4:** бриф и структура — только если контент пишем мы; дизайн-систему (3) — перенести из макета в `theme.json`, макеты (4) пропустить; дальше тексты → тема → сдача.

## Клиентский — доработка

Сайт живой: сначала доступы и копия сайта, потом вопросы по найденному.

**Порядок:** F0–F1 → `sync-down` и baseline (`WORKFLOW.md` → 1.2: коммит, тег, дамп БД) → анализ кода (шаг «анализ кода») → B (подтвердить найденное) → C → E → A (коротко) → F2–F5 → D.

**Особые вопросы:**

1. **Дочерняя тема есть?** (если анализ не нашёл `Template:` в `style.css`)
   Зачем: правки в дочерней теме не слетают при обновлении основной.
   - `создать дочернюю (рекомендую)` — для темы из маркета или от другого разработчика;
   - `правим тему напрямую` — тема написана под этот сайт и не обновляется извне.
2. **Кто ещё правит сайт и как часто?** (блок E, обязателен)
   Зачем: перед каждой задачей агент сверяется с сервером, чтобы не затереть чужие правки.

**Предзаполнение:**

- B — всё из анализа кода; архитектуру не менять (`CLAUDE.md` → «Лестница выбора подхода»).
- A. Дизайн — «без макета, в стиле текущего сайта» как первый вариант; контент — «даёт клиент».
- F5. Сайт с трафиком → `stage-auto`, если stage есть; иначе `guarded-auto` с предупреждением «правка сразу на живом сайте» или `manual`.

**Стеки по умолчанию:** по найденному (`classic` / `builder` / `fse`, `woo`, `acf`, `blocks`) + `wpcli` при WP-CLI = да. Большой незнакомый код — временно `triage`.

**Дальше:** карта проекта — skill `project-structure` (`WORKFLOW.md` → 1.3). SCSS-заготовка — только `abstracts/`, после проверки конфликтов.

## Клиентский — редизайн

Сайт живой, меняется внешний вид. Начало — как у доработки, затем выбор глубины редизайна.

**Порядок:** F0–F1 → `sync-down` и baseline → анализ кода → **R1–R3** → B → C → A (дизайн обязателен) → E → F2–F5 → D.

**Особые вопросы:**

1. **R1. Глубина редизайна?**
   Зачем: решает, остаётся ли текущая тема и архитектура или пишем новую.
   - `рестайл` — новый вид в текущей теме: стили, шаблоны, блоки; архитектура та же.
   - `новая тема` — тема пишется заново, контент и адреса страниц сохраняются; режим по лестнице (FSE рекомендую). Смена архитектуры (билдер → блоки, classic → FSE) — запись в `DECISIONS.md`.
2. **R2. Где собираем новый вид до запуска?**
   Зачем: живой сайт не должен ломаться, пока редизайн не готов.
   - `на stage (рекомендую)` — переключение на проде отдельным шагом после приёмки;
   - `неактивной темой на проде` — только для `новая тема`: заливка не задевает посетителей, просмотр через предпросмотр темы;
   - `сразу на проде` — только для мелкого рестайла.
3. **R3. Снимок старого сайта сделать?** `да (рекомендую)` / `нет`
   Зачем: после редизайна сверить, что не потеряны страницы, адреса, заголовки и скорость.
   При «да» — `project-base/redesign/`: список URL, `title` и `description` ключевых страниц, скрины 375 / 1440; при стеке `seo` — baseline `seo-drift`.

**Предзаполнение:**

- B — найденное в коде; при `новая тема` — режим новой темы отдельным вопросом.
- C. `новая тема` → новый слаг темы в `project.json` → `themes`; старую тему туда не добавлять (агент её не правит, читает как образец).
- A. Дизайн обязателен: Figma / Claude Design / без макета (план по `frontend-design`). Дизайн-система — предложить `/design-sync` из текущей темы как стартовую.
- F5. `stage-auto` при R2 = stage; при «неактивной темой» — `guarded-auto`.

**Стеки по умолчанию:** по найденному или по режиму новой темы; `figma` или `design`; `seo` + `quality` (рекомендую: сравнить до и после); `content`, если тексты переписываем; `motion` по блоку A; `wpcli` при WP-CLI = да.

**Дальше:** карта текущего кода — `project-structure`; при `новая тема` — этапы 3–8 из `WORKFLOW.md` → 1.4, переключение темы — только по команде пользователя.
