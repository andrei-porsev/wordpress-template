# Ручные шаги — каталог

Всё, что агент сделать не может или не должен: панели хостинга, пароли и ключи, установка программ, PATH, настройки Claude Code, решения клиента.
Как сообщать — `SKILL.md` → «Ручные шаги». Строки «СДЕЛАТЬ ВРУЧНУЮ» / «Сделать (человек)» из вывода скриптов — тоже ручные шаги.

Обязательность: **обяз.** — без шага этап не идёт; **жел.** — работа пойдёт, но хуже; **по выбору** — только если пользователь хочет.

## Машина (один раз, этап 10)

| Шаг | Обяз. | Зачем | Как | Проверка агентом |
|-----|-------|-------|-----|------------------|
| PHP в PATH | обяз. без SSH, иначе жел. | `php -l` до заливки | путь из `machine-check` → Параметры → Переменные среды → Path, перезапустить терминал | `machine-check --force` |
| `git config --global core.autocrlf input` | жел. | рабочая копия с LF, как на сервере | команда в своём терминале | `machine-check --force` |
| Перенормализация рабочей копии (`git rm --cached -r -q . && git reset --hard`) | жел. | файлы на диске с LF; только при чистом `git status` | свой терминал, в папке проекта | `git ls-files --eol` |
| phpcs + стандарт WordPress | по выбору | проверка PHP-кода хуком | `composer global require --dev wp-coding-standards/wpcs dealerdirect/phpcodesniffer-composer-installer` | `machine-check --force` |
| `~/.wp-template/servers.json` | по выбору | stage на своём VPS собирается сам | скопировать `servers.example.json`, заполнить | `stage-config build` без ошибки |
| Ключ PuTTY → OpenSSH | обяз. при `.ppk` | скрипты не читают `.ppk` | PuTTYgen → Conversions → Export OpenSSH key | `connect-check` |

SSH-ключ `ed25519` создаёт агент после «да» (`ssh-keygen`) — не ручной шаг.

## Claude Code (этап 10, на каждый проект)

| Шаг | Обяз. | Зачем | Как | Проверка |
|-----|-------|-------|-----|----------|
| Одобрить проектные хуки | обяз. | без них нет охраны и заливки | запрос при первом запуске / `/hooks` | `selftest.mjs` |
| Одобрить MCP `playwright` | обяз. | проверка вёрстки в браузере | `/mcp` → playwright | инструменты `mcp__playwright__*` есть |
| Авторизовать MCP `figma` | при Figma | чтение и запись макета | `/mcp` → figma → Authenticate | инструменты figma есть |
| Фрагмент `settings.json` (стек `seo`) | при SEO | подключение плагина `claude-seo` | вставить фрагмент из вывода `skills-sync activate` | `/seo` доступен |
| `/seo setup` (ключи Google, Gemini) | при SEO | данные Search Console, PageSpeed | запустить, войти в Google | `/seo google` |

## Сервер и доступы (этап 3)

| Шаг | Обяз. | Зачем | Как | Проверка |
|-----|-------|-------|-----|----------|
| Данные входа (хост, логин, пароль / ключ) | обяз. | без них нет сверки и заливки | в чат или письмо хостинга; пароль агент кладёт в json | `connect-check` |
| Включить SSH, добавить публичный ключ | жел. | WP-CLI, логи, быстрые проверки | панель хостинга (Plesk: подписка → SSH `/bin/bash`; SiteGround: SSH Keys Manager → Import); клиенту — письмо от агента | `connect-check` |
| Открыть порт SSH в фаерволе | при таймауте | иначе нет связи | панель хостинга; IONOS — ещё облачный фаервол | `connect-check` |
| `sftp-ftp.json` и `"sftp.config"` | при FTP | агент этот файл не открывает | по `sftp-ftp.json.example`, `.vscode/settings.json` → `"sftp.config": "sftp-ftp.json"` | `connect-check` |
| WP-CLI для пользователя подписки | жел. при SSH | база, администраторы, `verify-checksums` | установить `wp-cli.phar` в домашнюю папку (свой VPS — `project-ops` → `plesk.md`) | `connect-check`: WP-CLI да |
| PHP Plesk в PATH | при Plesk без chroot | `wp` без префикса — работает `guard-wpcli` (дамп перед изменениями) | свой VPS — команда для SSH Terminal из `stage-config build` (заодно ключ агента); иначе `~/.bashrc`: `export PATH=/opt/plesk/php/<версия>/bin:$PATH` (нет файла — создать, есть — в начало) | `ssh-exec.mjs -- wp core version` |
| Снять блокировку IP / разобраться со входом | при стопе «2 неудачных входа» | Fail2Ban | панель хостинга → Fail2Ban; исправить данные | `connect-check --reset-auth` после исправления |
| Подтвердить смену ключа сервера | при «сменился ключ» | защита от подмены | уточнить у хостинга | `connect-check --forget-host` |

## Копия, stage, база (этап 4, переезд, локальная копия)

| Шаг | Обяз. | Зачем | Как | Проверка |
|-----|-------|-------|-----|----------|
| Бэкап БД в панели хостинга | обяз. без SSH | точка отката базы | панель хостинга / плагин бэкапов | пользователь: «готово» |
| План «Stage» в Plesk | один раз на сервер | подписки stage одинаковые: SSH `/bin/bash`, Apache + nginx, noindex, без почты | `project-ops` → `plesk.md` → 1 | первая подписка: `connect-check --stage`, заголовок `X-Robots-Tag` |
| Создать stage (подписка, клон / импорт / установка) | при stage на VPS | копия для правок | `project-ops` → `plesk.md` → 2 | `connect-check --stage` |
| Пароль на stage (защита каталога) | обяз. при копии прода | копию не видят посторонние, клиент смотрит работу, WP-cron базы прода не шлёт письма до перехвата почты | свой VPS — «Защищённые паролем папки» → `/` **до клона**, свой у проекта; логин и пароль → `httpAuth` в `sftp-stage.json`, затем `stage-config auth` | `recon --stage`: сайт 200, без пароля — 401 |
| `noindex` в заголовках stage | жел. (свой VPS — из плана) | копия не попадёт в Google | панель / настройки веб-сервера | заголовок `X-Robots-Tag` |
| Удалить подписку stage | при сдаче, если stage не нужен | не копятся подписки | `project-ops` → `plesk.md` → 3 (сначала проверка агентом) | `ACCESS.md` → «Stage: удалён» |
| Тестовые ключи оплаты Woo на stage / локально | обяз. при магазине | без реальных списаний | настройки WooCommerce → платежи | пользователь: «готово» |
| Перенос всего сайта (архив, импорт) | при переезде / локальной копии | скрипты переносят только код | Duplicator, All-in-One WP Migration, WP Toolkit, импорт в LocalWP | `connect-check` / `local-exec status` |
| Запустить сайт в LocalWP / OSPanel | при локальной копии | WP-CLI и проверка нужны с запущенной базой | Start site | `local-exec status` |
| `wp-cli.phar` для локального сайта | при локальной копии | локальный WP-CLI | скачать официальный с wp-cli.org в корень сайта | `local-exec status` |
| Включить `WP_DEBUG_LOG` | при отладке | лог ошибок | `wp-config.php` — только на stage / локально (агент `wp-config` не правит) | `debug.log` появился |
| TTL DNS снизить, затем переключить DNS | при переезде | быстрое переключение | у регистратора / DNS-хостинга | сайт открывается с нового сервера |
| «Изменение адреса» в Search Console | при смене домена | перенос позиций | Search Console → настройки | пользователь: «готово» |

## Сайт и админка (этап 7)

| Шаг | Обяз. | Зачем | Как | Проверка |
|-----|-------|-------|-----|----------|
| Настройки плагина безопасности для пользователя агента | при 2FA / блокировках | агент не заблокирует себе вход | исключить `claude-agent` из 2FA на stage, разрешить вход | вход агента в браузере |
| Создать пользователя агента без SSH | без WP-CLI | закрытые страницы | админка → Пользователи → добавить (логин, роль из `site.md`) | вход агента |
| Действия только в админке (экспорт набора Elementor, сохранение настроек) | по задаче | агент в админке только смотрит | шаги даёт агент | результат в браузере |
| Удалить пользователя агента на проде | при сдаче | лишний вход клиенту не нужен | админка или `wp user delete` после «да» | `wp user list` |
| Решения клиента: `dev_old`, лицензии, Impressum | по аудиту | только клиент знает | письмо или звонок клиенту | ответ клиента в `DECISIONS.md` |

## Шаблон (не в каждом проекте)

Правки хуков и `settings.json` (часть D плана) — пользователь, по описанию агента; в инициализации не повторять.
План «Stage» в Plesk — один раз на сервер (`plesk.md` → 1); в инициализации — только если плана ещё нет.
