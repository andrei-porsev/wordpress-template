# Этап 2. О проекте и бриф

Пользователь — веб-разработчик, не маркетолог и не SEO-специалист: агент ведёт сам. На каждый вопрос брифа — сразу черновик ответа по нише,
пользователь говорит «да», «нет» или «вот так». Готовых формулировок не ждать.

## О проекте

### Новый сайт

| Вопрос | Зачем |
|--------|-------|
| Название проекта | из него агент предложит слаг темы, префикс, text-domain (этап 5) |
| Домен: есть (какой) / ещё нет | адрес для проверки; нет — прочерк |
| Вид сайта: лендинг / корпоративный / магазин / блог или медиа / каталог или сервис / портфолио | подсказывает стеки (магазин → `woo`) и набор страниц |
| Главные действия посетителя (заявка, покупка, запись, звонок) | из них — «Обязательные проверки» в `INDEX.md`: что работает после каждой правки |
| Языки: один / несколько (какие) | несколько → плагин перевода, `seo-hreflang`, строки через `__()` |
| Посетители: США / Европа / весь мир | Европа → GDPR: cookies, локальные шрифты и скрипты, политика конфиденциальности; Германия, Австрия, Швейцария — ещё страница Impressum |

**Вид сайта кнопками:** вариантов 6, в вопросе — не больше 4. Отсеять по известному (нет WooCommerce — без «магазина», нет портфолио-контента — без «портфолио»)
и в тексте вопроса назвать, что убрано и почему; остальное — через «Другое».

**Язык ↔ география:** язык сайта не совпадает со страной посетителей (английский сайт, клиника в Мюнхене) — спросить «нужна версия на <языке страны>?».
Зачем: местные ищут на своём языке, без версии эти запросы недоступны. Ответ — в «Языки» (`потом` — прочерк).

### Существующий сайт

Этап идёт после доступов и анализа — агент предзаполняет и показывает сводкой:

- название и домен — `wp option get blogname`, `wp option get siteurl` (без SSH — с главной страницы);
- вид сайта — по плагинам и главной (WooCommerce → магазин);
- языки — плагин перевода (WPML, Polylang) или `WPLANG` / язык сайта;
- назначение — агент читает главную и предлагает одно предложение.

Спросить только **главные действия посетителя** и **где посетители** — их из кода не видно.

## Языки работы

Для любого типа проекта, одним вопросом с тремя пунктами (инструмент вопросов: три вопроса, у каждого варианты «Английский», «Українська», «Русский»; свой — через «Другое»).
Не путать с языками сайта. Ответ — `INDEX.md` → «Языки работы» (решение 066).

| Пункт | Что регулирует | Подсказка агента |
|-------|----------------|------------------|
| Документация проекта | `project-base/`: карта, решения сайта, типы записей, QA, паспорт дизайна, бриф | язык, на котором пользователь читает документы |
| Комментарии в коде | своя тема, плагины, mu-плагины, `markup/` | английский — если код увидит клиент или другой разработчик за рубежом; иначе — как документация |
| Коммиты | сообщения новых коммитов в репозитории сайта | как документация; клиент читает историю — его язык |

> **Зачем:** на этих языках агент будет писать документы проекта, комментарии и коммиты; разговаривает с вами — на языке из настроек Claude Code.

Существующий сайт — подсказать по коду: язык комментариев в теме, язык прошлых коммитов («нашёл: комментарии на английском, коммиты на немецком — так и оставить?»).
Уже сделанные коммиты не переписываются ни при каком ответе.

## Бриф

| Версия | Когда |
|--------|-------|
| Короткий (вопросы 1, 2, 5; + 8 для регулируемых ниш) | всегда |
| Полный (все вопросы + дизайн) | пакеты «Тексты под ключ», «Редактура», «Базовое SEO»; типы «нужен дизайн» (новый и редизайн) |

Тип «нужен дизайн» — полный бриф сразу на этапе 2. Пакеты известны только на этапе 6 — **добрать до полного сразу после этапа 6**, не возвращаясь к остальному.
**Регулируемые ниши** (медицина, стоматология, право, финансы, алкоголь, азартные игры) — вопрос 8 «Чего нельзя обещать» в коротком брифе всегда:
реклама в них ограничена законом (например, HWG в Германии для медицины).

Существующий сайт — агент сначала читает тексты текущего сайта и заполняет бриф сам; пользователь правит.

| № | Вопрос | Черновик агента | Куда |
|---|--------|-----------------|------|
| 1 | Чем занимается клиент — своими словами | оффер: что, для кого, чем лучше | заголовок главной, `title` |
| 2 | Кто покупает | 2–3 портрета клиентов для ниши | тексты, структура |
| 3 | Почему выбирают их | подсказки: цена, скорость, опыт, гарантия, район | блок преимуществ |
| 4 | Конкуренты | нет своих — 3 сайта из поиска и что у них есть | чем отличиться |
| 5 | География: город / страна / онлайн | город → локальное SEO: карточка Google, `LocalBusiness`, страница контактов (`seo-local`) | стек `seo` |
| 6 | Что ищут в Google | список запросов (`seo-plan`, `seo-cluster`) — пользователь отмечает | страницы и заголовки |
| 7 | Тон: «ты» / «вы», строгий / дружелюбный | 2–3 пробные фразы на выбор | все тексты |
| 8 | Чего нельзя обещать | типичное для ниши: «гарантия результата», цены без оговорок | ограничения текстов |

Без DataForSEO частотность запросов неизвестна — список по логике ниши, поиску и конкурентам; сказать об этом одной строкой.

### Дизайн (полный бриф при «нужен дизайн»)

- Стиль: строгий / тёплый / технологичный / премиальный — на каждый 2–3 сайта-примера.
- Что есть у клиента: логотип, фирменные цвета, шрифты, фото.
- Референсы «нравится» и «не нравится» — по 2–3 сайта; нет — из конкурентов (вопрос 4).

- `project-base/design/references.md` — стиль и референсы (полный бриф с дизайном).
