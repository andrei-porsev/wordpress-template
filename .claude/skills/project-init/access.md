# Доступы при старте проекта

Отдельный блок опроса. Не прятать в «Процессы» одной строкой.
Ответы — в [`ACCESS.md`](../../../ACCESS.md) и конфиги **в том же ходе**, не в конце задачи.
Пароль в чат не цитировать. В ACCESS.md писать «в ssh.json» / «в sftp.json» / «в этом файле не храним».
«не знаю» / «потом» → прочерк. «нет» → `нет`, больше не спрашивать.

Что уже заполнено в ACCESS.md (не прочерк) — **не переспрашивать**, только подтвердить одной строкой.

Дискретные вопросы (да/нет, способ входа) — инструментом выбора с вариантами. URL, хост, пути, логины — текстом.

Если в блоке A уже есть домен — подставить в публичный URL и **подтвердить**, не спрашивать с нуля.

## F0. SFTP / FTP

Нужен, если SSH = «как SFTP»: без хоста SFTP наследовать нечего.
Если ACCESS → SFTP уже заполнен — пропустить.

1. Протокол: `sftp` / `ftp` / нет / не знаю
2. Host, port (SFTP 22, FTP 21), username
3. Auth: password / key. Ключ — `privateKeyPath` на этой машине
4. `remotePath` — корень WP на сервере

Запись: ACCESS → SFTP. Пароль только в `.vscode/sftp.json` (SFTP) или человек сам в `sftp-ftp.json` (FTP, агент файл не открывает).
Пустой host в sftp.json — остановиться, попросить заполнить.

## F1. SSH и WP-CLI

WP-CLI в шаблоне — **только на сервере** через `ssh-exec.mjs`. Локальный `wp` не предлагать.

### Вопросы (все, не сокращать)

1. Есть SSH? `да` / `нет` / `не знаю`
   - **нет** → ACCESS: `Есть: нет`, `WP-CLI: нет`. Остальное F1 не спрашивать.
   - **не знаю** → прочерки, `test` не запускать.
   - **да** → пункты 2–8.
2. Host: тот же, что SFTP? Если нет — хост.
3. Port: 22, если не сказали иное.
4. Username: тот же, что SFTP? Если нет — логин.
5. Auth: `как SFTP` / `password` / `key`
6. Если key — `privateKeyPath` (путь на этой машине, не содержимое).
7. `cwd` сайта: каталог WP на сервере. Часто = `remotePath` SFTP. Спросить явно.
8. WP-CLI на сервере: `да` (бинарь `wp`) / путь к бинарю / `нет` / `не знаю` (выяснит `test`).

Пароль SSH, если не «как SFTP»: принять в чате, записать **только** в `.vscode/ssh.json`, в ACCESS — «в ssh.json». Не повторять в ответе.

### Запись

1. ACCESS → SSH: Есть, Host, Port, Username, Auth, privateKeyPath, cwd, WP-CLI (пока как сказал пользователь; после `test` поправить).
2. `.vscode/ssh.json`: `host`, `port`, `username`, `password` или `privateKeyPath`, `cwd`, `wpCli`.
   «Как SFTP» — в ACCESS так и написать; в ssh.json пустые `host`/`username`/`password` (наследование из sftp.json). `cwd` и `wpCli` всё равно заполнить, если известны.
3. `wpCli` в json: `wp` или путь из п.8.

### Проверка в том же ходе

Если Есть = да и в json есть чем логиниться:

```bash
npm install --prefix .claude/skills/project-ops
node .claude/skills/project-ops/scripts/ssh-exec.mjs test
```

По выводу: `WP-CLI:yes` → ACCESS `WP-CLI: да` (или путь); `WP-CLI:no` → `нет`.
В чат: «SSH ок» или ошибка входа — **без** пароля.
`test` не запускать, если Есть = нет / не знаю / нет секрета в json.

В `INDEX.md` → «Команды», если WP-CLI да, рабочими строками:

```bash
node .claude/skills/project-ops/scripts/ssh-exec.mjs -- wp cache flush
node .claude/skills/project-ops/scripts/ssh-exec.mjs -- wp plugin list
```

Не вписывать голый `wp …` как локальную команду.

## F2. Сайт и браузер

Нужно, чтобы агент открывал витрину и админку, не спрашивая URL каждый чат.
Проверка в браузере — по этим полям. Нет MCP браузера в сессии — не выдумывать клики; в чате сказать, что MCP не подключён.

### Вопросы (все, не сокращать)

1. Публичный URL сайта (`https://…`). Prefill из блока A, подтвердить.
2. Stage / dev URL: другой адрес / «как публичный» / нет stage.
3. URL админки: полный или «`/wp-admin` от публичного» (записать абсолютный URL).
4. Пользователь админки. Нет — `нет` (агент в админку не входит).
5. Пароль админки: дать записать в ACCESS / «в этом файле не храним» / нет.
   Дан в чате и «записать» — в ACCESS. «Не храним» — агент не логинится сам.
6. Агент проверяет UI в браузере после правок? `да` / `нет`
7. Если п.6 = да: входить в админку? `да` / `нет` (да — только если есть пользователь; пароль «не храним» → вход не обещать).

### Запись

ACCESS → «Сайт и браузер»: все поля. Прочерки честные.

Если п.6 = да — в `INDEX.md` → «Обязательные проверки» пункт:
проверка в браузере по публичному URL из ACCESS.md (и админка — если вход = да).

Если п.6 = нет — в ACCESS `Проверка агентом в браузере: нет`, в проверках INDEX браузер не требовать.

### MCP браузера

Playwright MCP подключён по умолчанию (`.mcp.json` в корне, `enabledMcpjsonServers` в `.claude/settings.json`), профиль изолированный (`--isolated`: без сохранённых сессий, вход каждый раз тестовым пользователем).

Если п.6 = да:

1. Проверить, что в сессии есть инструменты `mcp__playwright__*`. Нет — сказать: `/mcp` → одобрить `playwright` (Node 20+, при первом запуске `npx` скачивает браузер).
2. **Домены.** Сверить флаг по `npx -y @playwright/mcp@latest --help` и предложить добавить в `args` в `.mcp.json`
   `--allowed-origins=<публичный URL>;<stage URL>` (через `;`, только origin: схема + хост). Сайт грузит шрифты, скрипты или картинки с CDN — добавить и их,
   иначе страница отрисуется не полностью. **Это не граница безопасности** (флаг не влияет на редиректы): запрет ходить на сторонние сайты дублирует правило `safety`.
3. ACCESS: `MCP браузера: playwright (.mcp.json)`.
4. Отказ — ACCESS: `MCP браузера: нет`. Проверка UI тогда на человеке; агент не притворяется, что открыл сайт.

П.6 = нет — ACCESS `MCP браузера: нет`; ключ `playwright` можно оставить в `.mcp.json`, он ничего не стоит, пока не вызван.

### Тестовый пользователь (если вход = да)

Для закрытых страниц — отдельный тестовый аккаунт (роль по задаче), не личная админка владельца.
ACCESS → «Сайт и браузер»: «Тестовый пользователь» (логин, роль; пароль — в ACCESS или «в этом файле не храним»).
Пароль в ответах не цитировать.

## F3. Figma

Нужно, чтобы агент читал макет по ссылке, не спрашивая файл каждый чат.
Нет MCP Figma в сессии — не выдумывать слои и отступы «на глаз»; в чате сказать, что MCP не подключён.

### Вопросы (все, не сокращать)

1. Есть макет в Figma? `да` / `создадим` / `нет` / `не знаю` (блок A уже ответил «рисуем с нуля» — это `создадим`, не переспрашивать)
   - **нет** → ACCESS: `Есть: нет`. Остальное F3 не спрашивать, ключ `figma` в `.mcp.json` не добавлять.
   - **не знаю** → прочерки.
   - **да** → пункты 2–3.
   - **создадим** → ACCESS: `Есть: создадим`, URL прочерком (агент запишет после `figma-create-new-file`). Спросить только команду/проект Figma,
     где создавать файл. MCP добавить как при «да». Предупредить: запись на канвас требует Dev или Full seat на платном плане Figma.
2. URL файла (`https://www.figma.com/design/…` или `figma.com/file/…`). Несколько файлов — списком.
3. Что верстать: весь файл / страницы / фреймы (имена или ссылки с `node-id`).

Токен и пароль Figma **не** принимать в ACCESS. Подключение — OAuth через `/mcp` (Authenticate).

### Запись

Если п.1 = да или создадим — дописать в `.mcp.json` ключ `figma`, не затирая Playwright:

```json

	"url": "https://mcp.figma.com/mcp"
}
```

Сказать: в чате `/mcp` → у `figma` выбрать Authenticate и разрешить доступ. Десктопный `127.0.0.1:3845` не предлагать, пока пользователь сам не попросил.

П.1 = нет — ACCESS `Есть: нет`, MCP-строку не выдумывать как «подключено».

## F5. Режим заливки

Как правки агента попадают на сервер (решение 012). Записать в ACCESS → «Заливка».

1. `guarded-auto` (по умолчанию): хук после каждой правки — `php -l`, бэкап файла с сервера, заливка, проверка сайта и `debug.log`, откат при ошибке. Нужен SSH/SFTP и публичный URL.
2. `stage-auto`: то же, но только на stage. Нужны `.vscode/sftp-stage.json` (и `ssh-stage.json`, если доступ другой) и Stage URL в ACCESS.
3. `manual`: агент заливает только по команде или после «да».

Нет SSH/SFTP или host пустой — заливка не работает, режим фактически `manual`; записать это в ACCESS.
Сайт с живым трафиком и критичный — предложить `stage-auto`.
