# Пакет «Перенос контента»

Страницы, записи, медиа со старого сайта на новый; старые адреса — 301 на новые. Вопросы пакета (откуда, объём, сохраняются ли адреса) — заданы на этапе 6.

## 1. Опись старого сайта — до переноса

- Список адресов: `sitemap.xml` старого сайта, Search Console → Страницы, или обход (агент, браузер, с разрешения пользователя для чужого домена).
- Записать в `project-base/content/migration-map.md`: старый адрес → новый адрес → тип (страница / запись / товар) → статус (`ждёт` / `перенесён` / `301` / `не переносим`).
- Скриншоты ключевых страниц «до» — `site.md` → «Скриншоты».

## 2. Перенос

| Откуда | Как |
|--------|-----|
| WordPress → WordPress | Инструменты → Экспорт (WXR) на старом → Импорт на новом (человек или `wp import` после «да»); медиа — с флажком «загрузить вложения» |
| Другая CMS / конструктор | экспорт в CSV / XML → плагин импорта (WP All Import) — человек; или вручную по карте |
| Статичный сайт | тексты — по карте в `project-base/content/<страница>.md`, затем в блоки / паттерны (агент); картинки — `wp media import` после «да» |

Без WP-CLI — `no-wpcli.md`. Тексты в новом стиле — правило `content`, скиллы `copy-editing`.

## 3. Редиректы

- Адреса меняются — 301 со старого на новый для каждой строки карты: плагин Redirection (импорт CSV из карты, человек или `wp redirection import` после «да») или `.htaccess` / nginx (человек, хостинг).
- Проверка: каждый старый адрес отвечает 301 → новый, новый — 200; цепочек 301 → 301 нет.

## 4. Сдача

- Все строки карты — `перенесён`, `301` или `не переносим` (с причиной).
- Картинки на месте, битых ссылок нет; `/seo audit` до / после.
- Search Console: новая карта сайта отправлена; при смене домена — «Изменение адреса».
