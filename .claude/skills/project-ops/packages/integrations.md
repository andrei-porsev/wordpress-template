# Пакет «Интеграции» — CRM, оплаты, рассылки, аналитика

**Агент работает только в тестовом режиме.** Боевые ключи, токены и пароли сервисов вводит человек — в настройки плагина или в `wp-config.php`; агент их не видит, не просит в чат и не пишет в файлы проекта.

## 1. Перед подключением

- Список сервисов и у кого аккаунт (вопросы этапа 6). Аккаунта нет — клиент заводит сам (агент аккаунты не создаёт).
- Тестовый режим у сервиса есть? (Stripe test mode, PayPal sandbox, тестовая воронка CRM, отдельный список рассылки.) Нет — подключение только на stage и только к тестовому списку / объекту.
- Европа: аналитика и пиксели — только после согласия на cookies (Complianz / CookieYes), запись в `DECISIONS.md`.

## 2. Подключение

1. Предпочтительно — официальный плагин сервиса (WooCommerce Stripe, Mailchimp for WooCommerce, плагин CRM); свой код — только для недостающего (стек `plugin` / `rest`, свой плагин `{stem}-core`).
2. Тестовые ключи вводит человек → 🖐 «Сделать вручную».
3. Вебхуки: адрес — stage; секрет вебхука — человек.

## 3. Проверка — тестовые сценарии

Для каждой интеграции — сценарий и результат в `project-base/content/integrations.md` (или `DECISIONS.md`):

| Сервис | Сценарий | Ожидание | Результат |
|--------|----------|----------|-----------|
| оплата | тестовый заказ тестовой картой | заказ «оплачен», письмо, запись в кабинете сервиса | … |
| CRM | отправка формы | лид в тестовой воронке с полями | … |
| рассылка | подписка | контакт в тестовом списке, двойное подтверждение (Европа) | … |
| аналитика | просмотр, событие формы | событие в отладке (после согласия на cookies) | … |

## 4. Боевой режим — человек

Инструкция пользователю: где переключить на боевые ключи, какие вебхуки сменить на прод, что проверить после (один реальный платёж на минимальную сумму с возвратом — по решению клиента).
Агент после переключения проверяет только то, что видно без ключей: формы отправляются, ошибок в консоли и `debug.log` нет.
