# Пакет «Сопровождение» — ежемесячный цикл

Команда пользователя — «сопровождение за <месяц>». Периодичность и получатель отчёта — `INDEX.md` → «Профиль проекта» → «Пакеты».
Обновления — **сначала на stage**, потом на прод. Нет stage — обновлять на проде только после бэкапа и по одному плагину.

## 1. Проверка до обновлений

```bash
node .claude/skills/project-ops/scripts/session-check.mjs
node .claude/skills/project-ops/scripts/recon.mjs
```

Записать для отчёта: версии WordPress, плагинов и тем, итог безопасности (🟢 / 🟡 / 🔴), ошибки в `debug.log`, ответ сайта.
🔴 — стоп, обновления не делать, сообщить пользователю (`recon.md` → решения).

## 2. Бэкап

Прод: `ssh-exec.mjs -- wp db export ../claude-backup-<дата>.sql` (после «да»; хук сделает дамп сам) + бэкап файлов средствами хостинга (человек). Без SSH — `no-wpcli.md`.
Проверить, что бэкапы хостинга вообще делаются и свежие (человек: дата последнего бэкапа в панели).

## 3. Обновления на stage

1. Синхронизировать stage с продом (весь сайт — человек, WP Toolkit «Синхронизировать» / staging хостинга).
2. Обновить: ядро → плагины → темы. С WP-CLI: `wp core update`, `wp plugin update --all --dry-run` (список), затем по одному или пачкой после «да»; без WP-CLI — админка, человек.
3. Проверить stage: главная, страницы главных действий посетителя (`INDEX.md` → «Обязательные проверки»), формы, брейкпоинты темы (`layout-check`), консоль, `debug.log`.
4. WooCommerce обновился — сверить `@version` переопределений в теме (WooCommerce → Статус → Шаблоны).
5. Что-то сломалось — откат на stage, на прод это обновление не идёт; причину — в отчёт.

## 4. Обновления на проде

Те же версии, что прошли на stage. После — та же проверка, что в 3.3; `session-check` — версии совпадают со stage.

## 5. Отчёт клиенту

`project-base/reports/maintenance-<ГГГГ-ММ>.md`, язык — как с клиентом (`brief.md` → тон). Отправляет пользователь (агент письма не шлёт).

```markdown

## Итог

## Обновлено
| Компонент | Было | Стало |
|-----------|------|-------|
| WordPress | … | … |
| <плагин> | … | … |

## Безопасность
- Проверка файлов ядра и плагинов: <совпадают / найдено …>
- Подозрительное: <нет / …>

## Скорость и ошибки
```

## 6. После

Коммит отчёта; `ACCESS.md` → «Последняя выкатка» не трогать (это не код); следующая дата — в `INDEX.md` → «Сделать вручную» или напоминанием пользователю.
