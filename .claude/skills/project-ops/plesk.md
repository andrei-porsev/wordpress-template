# Stage на своём VPS (Plesk): план «Stage», подписка на проект, конец проекта

Свой VPS (Plesk; проверено на IONOS) — только stage и промежуточные копии. Адрес stage — `{project}.<домен stage>` (домен — в `~/.wp-template/servers.json` → `stageUrl`), DNS зоны обслуживает сам Plesk.
В панели всё делает **человек**: доступа администратора Plesk у агента нет (решение 033). Агент ведёт по шагам — каждый шаг блоком «🖐 Сделать вручную» (`project-init` → `manual-steps.md`) — и проверяет результат.
Человеку — пошаговая справка `/howto stage` (`.claude/skills/howto/stage.md`): там тот же порядок и значения подписки; правишь значения здесь — поправь и там.

Один проект — одна подписка: свой системный пользователь, своя БД, свой пароль на каталог; удаление подписки убирает всё сразу.
Названия ниже — по русскому Plesk Obsidian 18.0.81; в другой версии искать по смыслу.

## 1. План «Stage» — один раз на сервер

**Тарифные планы → Добавить план**, имя `Stage`.

| Вкладка | Значение | Зачем |
|---------|----------|-------|
| Ресурсы | перерасход диска и трафика разрешён + уведомления; диск 10 ГБ, уведомлять с 8 ГБ; трафик — как есть; домены 1; субдомены, псевдонимы 0; почтовые ящики, рассылки 0; доп. FTP 0; базы данных 1; веб-пользователи 0; срок — без ограничений; сайты WordPress 1; резервные копии WordPress 3; Smart Update 0; Rank Tracker 0 | stage не разрастается; второй WordPress в подписку не встанет |
| Память, процессор, ввод-вывод диска | процессор 100 % (одно ядро), память 2048 МБ (уведомлять с 1600), чтение и запись диска — без ограничений | зависший импорт или cron не кладёт сервер; копирование и дампы не тормозятся |
| Права | **«Управление доступом к серверу по SSH» → «Разрешено предоставлять доступ к любой оболочке»** (иначе на вкладке «Параметры хостинга» `/bin/bash` не задать); всё про WP Toolkit — включено; «Управление настройками хостинга», «Управление планировщиком», «Удалённый доступ для пользователей баз данных», «Выбор сервера баз данных» — выключено; остальное по умолчанию | владелец подписок — сам человек, клиенты в Plesk не входят |
| Параметры хостинга | **SSH-доступ под системным пользователем подписки — `/bin/bash`**; SSL/TLS и перенаправление HTTP → HTTPS 301 — включены; веб-статистика — выключена; дисковая квота — без ограничений (жёсткий лимит оборвал бы импорт) | WP-CLI и `php` работают; в chroot их нет |
| Настройки PHP | 8.3, «Приложение FPM обслуживается Apache»; остальное по умолчанию (`memory_limit` 512M, `display_errors` off). По желанию: `upload_max_filesize` / `post_max_size` 256M, `pm.max_children` 5 | версию под прод клиента меняют в подписке |
| Веб-сервер | режим прокси — включён; кеширование nginx — выключено; **дополнительные директивы nginx:** `add_header X-Robots-Tag "noindex, nofollow" always;`; директивы Apache — пусто. Размер тела запроса — как `post_max_size` | директива nginx ставит заголовок и на статику, и на ответы Apache (страницы WP); Apache-строка дала бы дубль |
| Почта | «Не настроено» — Plesk требует галочку «Безвозвратное удаление всех почтовых ящиков…»: ставить, **только если у плана 0 подписок** (Тарифные планы → столбец подписок); веб-почта и автообнаружение — выключены | ни ящиков, ни почтовых DNS-записей |
| Дополнительные услуги | WP Toolkit — «Нет»; SSL It! — «Обеспечить защиту сайтов с помощью бесплатных SSL/TLS-сертификатов» | WordPress приходит клоном / импортом, пустая установка заняла бы единственную БД; Let's Encrypt выпускается и продлевается сам |

**Важно:**

- Правки вкладки «Веб-сервер» доходят **только до новых подписок** — у существующих менять в подписке: Хостинг и DNS → Настройки Apache и nginx.
- «Не настроено» убирает ящики, но **не исходящую почту PHP**: `mail()` уходит через sendmail сервера. Письма WordPress глушит «безопасный stage» (раздел 2, шаг 7) — до него база прода не должна «просыпаться» (шаг 5 раньше шага 6).
- Шаблон виртуального сервера (Инструменты и настройки) для `.bashrc` не годится: «Загрузить» принимает только архив и заменяет весь шаблон. `.bashrc` — командой из шага 3.
- Security Policy не нужна: подписку на поддомен домена из другой подписки Plesk создаёт сам, зону поддомена и делегирование — тоже.

## 2. Подписка на проект

Копию **существующего** сайта — только после проверки безопасности (`project-init` → `recon.md`): заражённое на свой сервер не переносим.

1. **Подписки → Добавить подписку → «Пустой сайт»**: домен `{project}.<домен stage>`, тарифный план «Stage», имя пользователя `{project}_dev`, пароль — сгенерировать (не нужен, вход по ключу).
   «После создания подписки перейти к настройке её параметров» — **снять** (иначе подписка отвяжется от синхронизации с планом).
   Предупреждение «Домен не может быть разрешён» сразу после создания — норма: через минуту домен резолвится.
2. **SSL/TLS-сертификаты:** выпускается сам; «Проблемы будут устранены автоматически» — либо подождать, либо «Установить» → Let's Encrypt: имя домена + «www», HTTP (http-01). HSTS не включать.
3. **Агент:** `stage-config.mjs build <project>` → план → «да» → `--yes`. Скрипт пишет `.vscode/sftp-stage.json`, `ssh-stage.json` и печатает **команду для SSH Terminal**.
   **Человек:** подписка → SSH Terminal → вставить команду одной строкой → Enter. Она добавляет публичный ключ агента в `~/.ssh/authorized_keys`, ставит PHP Plesk в PATH через `~/.bashrc` и выводит версии PHP и WP-CLI.
   Без команды — подписка → SSH Keys → добавить строку из `<ключ>.pub` (файл с `.pub`, приватный не трогать) и `.bashrc` вручную.
4. **Агент:** `connect-check.mjs --stage` — ключ, путь, `php`, `wp`. На пустой подписке «`wp-config.php` нет» — норма. Не прошло — таблица диагностики (`project-init` → `access.md`), не больше 2 попыток входа.
5. **Пароль на каталог — до клона**: подписка → «Защищённые паролем папки» → добавить папку `/`, пользователь и пароль **свои для проекта** (их получает клиент).
   Пароль в настройках веб-сервера переживает клонирование; пока он стоит, запросы WP-cron к сайту получают 401 — база прода не рассылает письма до шага 7.
   Логин и пароль → `.vscode/sftp-stage.json` → `httpAuth { "user", "password" }` (заготовку пишет `build`): вписывает человек или агент из сообщения (в ответах не повторять); затем `stage-config.mjs auth <project>` → `.vscode/playwright-mcp.json`.
   Это **не** пароль подписки и не FTP: при входе по ключу пароль подписки не нужен нигде, поля `password` в конфиге нет. Человеку говорить так же — «логин и пароль защищённой папки, окно пароля в браузере».
6. **WP Toolkit:** прод на этом же сервере → **Клонировать**; на хостинге клиента → **Импортирование сайта**; нового сайта ещё нет → **Установить** (автообновления выключить). Повторный клик «Установить» даёт «Достигнуто ограничение…» — сайт уже стоит.
   Сайт в локальной копии (LocalWP, OSPanel) → **Установить**, затем человек: на локальном — UpdraftPlus (база + все файлы, скачать все части) или All-in-One WP Migration → на stage тот же плагин → восстановить.
   Вход после восстановления — данные локального сайта. **Агент:** `wp search-replace '<локальный URL>' 'https://<stage>' --dry-run` → «да» → без `--dry-run` (бесплатный UpdraftPlus адреса не меняет).
7. **Агент, «безопасный stage»** (`stage.md` → 2) после «да»: **первым** — Disable Emails + WP Mail Logging, затем индексация, cron, `search-replace` домена.
   Изменения через WP-CLI WP Toolkit сам не видит — человек жмёт ⟳ у названия сайта.
8. **Агент:** браузер — stage открывается без окна пароля, `X-Robots-Tag: noindex, nofollow` один раз у страницы и у файла; `ACCESS.md` → «Окружения»: Stage — свой VPS, Stage / dev URL, «Пароль на stage: в `sftp-stage.json` → `httpAuth`, выдан клиенту — да / нет».

Пароль на каталог в `ACCESS.md` не пишется — только где лежит. Клиенту его передаёт человек.

## 3. Конец проекта

Stage либо остаётся (сопровождение, будущие доработки — перед новой задачей освежить с прода: WP Toolkit → Копировать данные, затем «безопасный stage»), либо удаляется.

**Удалить:**

1. Агент проверяет, что ничего не потеряется: сайт работает на проде, последняя выкатка сделана, `session-check` — незалитого нет.
   Сделанное только в базе stage (страницы, настройки), чего нет на проде, — списком пользователю; решает он.
2. Человек: подписка → «Удалить подписку» — БД, файлы, пользователь и сертификат уходят вместе с ней.
3. Агент после «да»: `ACCESS.md` → «Stage: удалён <дата>»; режим `stage-auto` → `guarded-auto` или `manual` (`ACCESS.md` → «Заливка»); коммит.
   Конфиги `.vscode/sftp-stage.json`, `ssh-stage.json`, `playwright-mcp.json` **остаются** — при новом stage их обновит `stage-config build`.

Агент к удалённому stage не обращается (`--stage` не использует), пока в `ACCESS.md` не появится новый.

**Клиент вернулся:** новая подписка по разделу 2 с прода (Клонировать / Импортирование), `stage-config build` обновит конфиги, новый пароль на каталог → `httpAuth` и `auth`. В git — код, документация, настройки агента и вся история; БД и медиатека — с прода.
