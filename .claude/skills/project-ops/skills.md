# Скиллы: стеки и версии

Манифест — `.claude/skills.json` (решение 016): откуда каждый скилл, закреплённая версия (`commit`, `tree`, `hash`), стеки.
Руками в манифесте правят только `sources`, `stacks`, `core`; остальное пишет скрипт.

**Сторонние скиллы шаблон не хранит.** В манифесте — проверенная версия; `activate` и `install` скачивают ровно её из апстрима,
сверяют `tree` и `hash` и проверяют содержимое. Свои скиллы шаблона (`source: "local"`) лежат в `.claude/skills-optional/`.

```bash
node .claude/skills/project-ops/scripts/skills-sync.mjs <команда>
```

## В проекте

| Задача | Команда |
|--------|---------|
| Что есть и что подключено | `list` |
| Подключить стек | `activate <стек…>` |
| Доставить или вернуть закреплённую версию | `install <имена>` (`--force` — заменить копию с правками проекта) |
| Подключить с новыми находками проверки | тот же вызов с `--accept` — **только после «да» пользователя** |
| Отключить стек | `deactivate <стек…>` |

Новые версии скиллов приходят **только с обновлением шаблона** (по просьбе пользователя, [template.md](template.md)): пробный прогон
показывает, какие подключённые скиллы сменят версию, какие файлы изменятся и что нашла проверка; `--apply` ставит их через `install`
отдельным коммитом. Апстрим проект сам не опрашивает, `check`, `review`, `update`, `add` в проекте не работают.

### Проверка при скачивании

Каждое скачивание — `activate`, `install`, обновление шаблона — независимо проверяет скачанное:

- `tree` и `hash` не совпали с манифестом — **стоп**, скилл не подключается, вариантов нет;
- проверка содержимого (`skills-lib.mjs` → `scanSkill`): исполняемые и бинарные файлы, скрытые символы Unicode,
  указания агенту обойти правила или скрыть действия от пользователя, правка настроек Claude Code, «скачать и выполнить»;
  в скриптах ещё сеть, запуск команд, удаление файлов, доступ к секретам (`.env`, `wp-config`, ключи, `ACCESS.md`), закодированный код;
- находки совпали с принятыми при разборе в шаблоне (`accepted`) — подключается, находки печатаются;
  новые находки — не подключается: показать пользователю, после его «да» — с `--accept`.

Итог каждого скачивания — строкой в `.claude/.state/audit.log`.

## В репозитории шаблона

| Задача | Команда |
|--------|---------|
| Новые версии в апстриме | `check` |
| Разобрать новую версию | `review <имена>` или `review --all` (`--full` — дифф целиком) |
| Закрепить разобранную версию | `update <имена> --apply` — **только после «да» пользователя** |
| Не напоминать про эту версию | `ignore <имена>` |
| Новый скилл из известного источника | `add <имя> --source <id> --path <путь> [--stack <стек>] [--exclude <путь,…>]` |

`review` скачивает закреплённую и новую версии во временную папку и печатает: список файлов, дифф, смену лицензии,
находки проверки (новые против прежней версии). По этому отчёту агент пишет пользователю разбор: что изменилось по сути,
что нашла проверка и безопасно ли, вывод. После «да» — `update --apply`: в манифест пишется ровно разобранная версия
и отпечаток её находок (`accepted`); файлы в шаблон не кладутся. Коммит — «Скиллы: версии <имена>».

`exclude` (например `scripts`, если скилл качает и запускает бинарники) хранится в манифесте и действует при каждом скачивании;
скилл в корне репозитория — `--path .` и `exclude` для служебного (`README.md`, `.github`, манифесты плагинов).
`add` с находками проверки — тоже только после разбора и «да» (`--accept`).

### Проверка при старте сессии

Хук `SessionStart` вызывает `check --hook`. В шаблоне — сеть не чаще раза в сутки (иначе кэш `.claude/.state/skills-sync.json`),
сообщает о новых версиях: одной строкой сказать пользователю, разбор — по его просьбе. В проекте апстрим не опрашивается:
хук сообщает только о начатом и не доведённом обновлении шаблона (миграция, конфликты, невлитая ветка); о новых версиях — нет (решение 059).

## Правила

- Копию с правками проекта скрипт не перезаписывает (`install` без `--force`, обновление шаблона). Свою доработку держи отдельным
  правилом или скиллом, а не правкой чужого. Если правка нужна насовсем — в шаблоне `source: "local"` и папка в `skills-optional/`.
- Лицензии источников — `sources` → `license` и таблица в `THIRD-PARTY-NOTICES.md`; новый источник — с лицензией там и там.
- Нет сети или апстрим удалил коммит — скилл не подключится, скрипт скажет причину; уже подключённые в `.claude/skills/` работают.
- Плагины (стек `seo`) обновляет Claude Code, не этот скрипт; `activate` только печатает фрагмент для `.claude/settings.json` —
  его вносит человек (хуки и настройки агенту закрыты).
- Новый скилл, которого нет ни в одном источнике манифеста, — сначала источник в `sources` (человек), потом `add`.
- Сеть — только `git ls-remote`, `git clone` и `git fetch` во временную папку системы; `curl`/`wget` не нужны.

## Подключение в `.claude/settings.json` (делает человек)

Агент этот файл не правит (решение 019). Слить с существующими ключами, ничего не удаляя:

```json
{
	"permissions": {
		"allow": [
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs check*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs list*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs review*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs install*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs update*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs ignore*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs activate*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs deactivate*)"
		],
		"ask": [
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs *--apply*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs *--force*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs *--accept*)",
			"Bash(node .claude/skills/project-ops/scripts/skills-sync.mjs add*)"
		]
	},
	"hooks": {
		"SessionStart": [
			{
				"matcher": "startup|resume",
				"hooks": [
					{
						"type": "command",
						"command": "node \"$CLAUDE_PROJECT_DIR/.claude/skills/project-ops/scripts/skills-sync.mjs\" check --hook",
						"timeout": 60
					}
				]
			}
		]
	}
}
```

`ask` сильнее `allow`: `--apply`, `--force` и `--accept` всегда спросят, даже при разрешённых `update`, `install`, `activate`.
В шаблоне хук задерживает первый ответ агента только раз в сутки, когда ходит в сеть (обычно 3–6 с, не больше ~40 с); в остальные старты читает кэш.
