# Обновление проекта до версии шаблона

Скрипт — `template-update.mjs` в папке **шаблона**, путь к проекту — аргументом (решение 032). Шаблон берётся из последнего коммита.
Метка версии проекта — `.claude/template.json` (пишет скрипт); версия и категории файлов шаблона — `.claude/template/manifest.json`.

```bash
node "<шаблон>/.claude/skills/project-ops/scripts/template-update.mjs" "<проект>"            # пробный прогон, ничего не меняет
node "<шаблон>/.claude/skills/project-ops/scripts/template-update.mjs" "<проект>" --apply    # после «да»
```

Путь к шаблону — `.claude/template.json` → `source.path`; у проекта без метки — спросить у пользователя.

## Когда

- При старте сессии строка «Шаблон: доступна X» (`skills-sync check --hook`, раз в сутки) — одной строкой предложить. Отказ — напомнится завтра.
- «Шаблон: незавершённая миграция» — доделать часть агента (ниже, шаг 5).

## Процедура

1. **До обновления:** в проекте всё закоммичено; сверка с сервером (`sftp-sync.mjs compare`) — отличий нет или скачаны и закоммичены (на проде источник правды — сервер).
2. **Пробный прогон** — показать пользователю отчёт: заменить / добавить / удалить / объединить / конфликты, стеки скиллов, защищённые файлы, миграции.
   Проект без метки: опора — коммит, где появился `.claude/settings.json` (иначе `--base <коммит>`).
3. **«Да» → `--apply`:** тег `before-template-update-<версия>`, ветка `template-update`, бесконфликтное применяется, метка, коммит.
4. **Конфликты** — по каждому показать разницу и решить с пользователем:
   `--take template <путь>` (взять шаблонный) · `--take project <путь>` (оставить проектный) · `--take merge <путь>` (маркеры `<<<<<<<` → поправить → `--take project <путь>`). Коммит.
5. **Миграции:** инструкция из отчёта (`.claude/template/migrations/<версия>.md`) — по шагам, с показом разницы, коммиты; затем `--done <версия>`, коммит метки.
6. **Хуки и `settings.json` — человек** в своём терминале: `… "<проект>" --protected` (скрипт сам спрашивает y/n; агент эту команду не запускает).
   Если в шаблоне есть ожидающие правки настроек — сначала человек на шаблоне: `… . --protected`, затем агент коммитит шаблон.
7. **Проверка:** перезапуск Claude Code в проекте → `node .claude/skills/project-ops/scripts/install-deps.mjs` (зависимости скриптов могли измениться), `node .claude/hooks/selftest.mjs`, `connect-check.mjs`, сайт в браузере; режим заливки авто — пробная безвредная правка в теме (комментарий) и проверка, что хук залил и сайт жив.
8. **Доинициализация:** `project-init`, повторный запуск — только поля-прочерки профиля.
9. Пользователь смотрит итог и сливает `template-update` в основную ветку, пуш. Откат — `git checkout main && git branch -D template-update` (тег остаётся).

## Что скрипт не трогает

Проектные файлы (`ACCESS.md`, `project.json`, карты, решения проекта, `.vscode/sftp*.json`, `ssh*.json`, `wp-content/`) — только механика миграций.
`settings.local.json`, `.claude/.state/`. Хуки и `settings.json` — только в `--protected`. Планы шаблона (`project-base/plans/`) в проекты не попадают.
Подключённые скиллы и правила (`.claude/skills/<стек>`, `.claude/rules/<стек>.md`) обновляются из `*-optional` шаблона; стеки — из `skills.json` → `active`,
у проекта без манифеста — по составу подключённых копий.
