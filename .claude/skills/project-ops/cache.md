# Кеш сайта после заливки

Кеш страниц и минификации отдаёт посетителям старый CSS / JS и старую разметку, пока его не сбросят (решение 037).
Что стоит на сайте и как сбрасывать — `ACCESS.md` → «Заливка» → «Кеш сайта». Пусто или прочерк — заполнить по разделу ниже, не искать заново в каждой задаче.

## Когда сбрасывать

После заливки CSS, JS или шаблона, если в «Кеш сайта» есть кеш страниц, минификация или CDN.
Объектный кеш (`wp cache flush`) стили не трогает — его хватает только для правок данных.

- **Есть команда** (таблица ниже, проверена `wp help <команда>` на этом сайте) — агент запускает сам после заливки, без вопроса:
  `node .claude/skills/project-ops/scripts/ssh-exec.mjs -- wp <команда>` (stage — с `--stage`). Хук `guard-wpcli` пропускает сброс кеша без подтверждения.
- **Нет команды** — один вопрос за задачу: «Сбросить кеш <плагин>: <путь в админке>?». Сбрасывает человек; агент ждёт ответа.
  В админке агент кнопки сброса сам не нажимает (правило `safety`).
- До сброса задача не «готово»: в отчёте — «залито, посетители увидят после сброса кеша».

## Команды сброса

| Плагин (слаг) | Команда WP-CLI | Примечание |
|---------------|----------------|------------|
| LiteSpeed Cache (`litespeed-cache`) | `wp litespeed-purge all` | |
| W3 Total Cache (`w3-total-cache`) | `wp w3-total-cache flush all` | |
| SiteGround Optimizer (`sg-cachepress`) | `wp sg purge` | в части версий 7.x команда сбоила — проверить ответ |
| WP Rocket (`wp-rocket`) | `wp rocket clean --confirm` | только с пакетом `wp-media/wp-rocket-cli`; ставит человек |
| WP Super Cache (`wp-super-cache`) | `wp super-cache flush` | только с пакетом `wp-cli/wp-super-cache-cli`; ставит человек |
| WP-Optimize (`wp-optimize`) | — | WP-CLI только в Premium; вручную: WP-Optimize → Кеш / Минификация → сброс |
| Autoptimize (`autoptimize`) | — | вручную: сброс кеша в настройках Autoptimize или в его меню на панели администратора |
| Кеш хостинга, CDN (Cloudflare и др.) | — | кнопка в панели хостинга / CDN — человек |

Плагина нет в таблице — `wp help` по его слагу; команды нет — «вручную» с путём в админке. Команду через `wp eval` (функция плагина) не собирать.

## Заполнить «Кеш сайта»

1. `recon.mjs` — строка «Плагины кеша» (по списку плагинов) и «кеш» по заголовкам ответа.
2. С WP-CLI — активен ли: `ssh-exec.mjs -- wp plugin list --status=active --fields=name --format=csv`.
3. Слои: страницы / минификация CSS·JS / CDN — по настройкам плагина в админке (смотреть, не менять) или со слов человека.
4. Записать: `WP-Optimize: страницы, минификация CSS·JS; сброс — вручную: WP-Optimize → Минификация, сброс кеша`.

## Проверка, что посетитель видит правку

После сброса проверка — по CSS, который отдаёт сайт, а не по подставленному (правило `layout-check` → «Что отдаёт сайт»).
