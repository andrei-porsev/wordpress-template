# Stage на своём VPS (Plesk)

🖐 — делаете вы в Plesk или в админке сайта, 🤖 — агент. «Скажите агенту» — готовая фраза, можно копировать.
`<project>` — короткое имя проекта латиницей (например, `siteb`); адрес stage — `<project>.stage.example.com`.
Значения полей Plesk сверены с `.claude/skills/project-ops/plesk.md` — правите там, правьте и здесь.

## Шаг 0. План «Stage» — один раз на сервер

Тарифные планы → «Stage» уже есть — пропустить.

🖐 Тарифные планы → Добавить план, имя `Stage`, значения по вкладкам:

→ вывести: `.claude/skills/project-ops/plesk.md` → «1. План «Stage» — один раз на сервер» (таблица и «Важно»)

## Шаг 1. Подписка

🖐 Подписки → Добавить подписку:

| Поле | Значение |
|------|----------|
| Тип | «Пустой сайт» |
| Доменное имя | `<project>.stage.example.com` |
| Тарифный план | `Stage` |
| Имя пользователя | `<project>_dev` — на это имя агент пишет конфиги |
| Пароль | «Сгенерировать» — не понадобится, агент входит по ключу |
| «После создания подписки перейти к настройке её параметров» | **снять** — иначе подписка отвяжется от плана |

- [ ] «Домен не может быть разрешён» сразу после создания — норма, через минуту пройдёт.
- [ ] Старая подписка этого проекта есть — сначала удалить её (шаг «Конец проекта»), потом создавать.

## Шаг 2. SSH и FTP

Отдельно ничего не создавать: пользователь подписки — он же SSH и SFTP, дополнительных FTP-аккаунтов не нужно (в плане 0).

- [ ] 🖐 Подписка → Хостинг и DNS → Параметры хостинга → «Доступ к серверу по SSH» = `/bin/bash`.
  Стоит «Запрещено» или `/bin/bash (chrooted)` — в плане не включено «Разрешено предоставлять доступ к любой оболочке» (вкладка «Права»): поправить в плане, не в подписке.

## Шаг 3. SSL

- [ ] 🖐 Подписка → SSL/TLS-сертификаты: выпускается сам. «Проблемы будут устранены автоматически» — подождать или «Установить» → Let's Encrypt: домен + `www`, проверка HTTP. HSTS не включать.

## Шаг 4. Доступ агента

1. 🤖 Скажите агенту: «Создай конфиги stage для `<project>`». Агент покажет план (`stage-config build`) → ваше «да» → запишет `.vscode/sftp-stage.json`, `ssh-stage.json` и напечатает команду.
2. 🖐 Подписка → SSH Terminal → вставить команду **одной строкой** → Enter. Она добавит ключ агента и PHP в PATH, в конце выведет версии PHP и WP-CLI.
3. 🤖 Скажите агенту: «Вставил». Агент проверит связь (`connect-check --stage`); на пустой подписке «`wp-config.php` нет» — норма.

## Шаг 5. Пароль на весь stage — до сайта

Пока пароль стоит, посторонние сайт не видят, а WP-cron не запускается — копия базы не рассылает письма до шага 7.

1. 🖐 Подписка → «Защищённые паролем папки» → Добавить защищённую папку: путь `/`, пользователь и пароль — **свои для этого проекта** (их получит клиент).
2. 🖐 Логин и пароль — в `.vscode/sftp-stage.json` → `"httpAuth": { "user": "…", "password": "…" }` сами или сообщением агенту (в ответах он их не повторяет).
3. 🤖 Скажите агенту: «Пароль stage вписан, подключи браузер». Агент: `stage-config auth <project>` → `.vscode/playwright-mcp.json`; дальше 🖐 `/mcp` → переподключить playwright.

## Шаг 6. Сайт на подписку — один из вариантов

Повторное «Установить» в WP Toolkit пишет «Достигнуто ограничение…» — сайт уже стоит.

**А. Копия сайта с этого же сервера**
- [ ] 🖐 WP Toolkit → у исходного сайта «Клонировать» → цель — подписка `<project>.stage.example.com`.

**Б. Копия с хостинга клиента** — сначала проверка безопасности прода (агент, `project-init`): заражённое не переносим.
- [ ] 🖐 WP Toolkit → «Импортирование сайта» → доступы хостинга клиента.

**В. С локальной копии (LocalWP, OSPanel)**
1. 🖐 WP Toolkit → «Установить»: автообновления выключить; логин и пароль администратора — любые, их заменит база из копии.
2. 🖐 На локальном сайте: UpdraftPlus → «Создать резервную копию» (база + все файлы) → скачать **все** части (db, plugins, themes, uploads, others).
   Или All-in-One WP Migration → Экспорт → Файл (бесплатная версия ограничена размером загрузки на сервере).
3. 🖐 В админке stage: поставить тот же плагин → UpdraftPlus → Настройки/Существующие копии → «Загрузить файлы резервной копии» → «Восстановить» все части.
   После восстановления вход в админку stage — логином и паролем **локального** сайта.
4. 🤖 Скажите агенту: «Сайт восстановлен из локальной копии `<локальный URL>`». Агент проверит `wp search-replace '<локальный URL>' 'https://<project>.stage.example.com' --dry-run` и после «да» заменит
   (бесплатный UpdraftPlus адреса не меняет, All-in-One — меняет сам).

**Г. Сайта ещё нет**
- [ ] 🖐 WP Toolkit → «Установить», автообновления выключить.

## Шаг 7. «Безопасный stage» — сразу после сайта

1. 🤖 Скажите агенту: «Сделай безопасный stage». Агент после «да»: **первым** — перехват почты (Disable Emails + WP Mail Logging), затем запрет индексации, список cron-задач, домен в базе.
2. 🖐 WP Toolkit → ⟳ у названия сайта (изменения WP-CLI он сам не видит).
3. 🖐 WooCommerce есть — Платежи → тестовые ключи (ключи — только вы).
4. 🖐 Плагины SMTP (WP Mail SMTP и подобные) — агент спросит, отключать ли; письма и так глушит Disable Emails.

## Шаг 8. Проверка

- [ ] 🤖 Агент: stage открывается без окна пароля в его браузере, заголовок `X-Robots-Tag: noindex, nofollow` один раз; записывает «Окружения» в `ACCESS.md`.
- [ ] 🖐 Вы: открыть `https://<project>.stage.example.com` — окно пароля, после входа сайт как ожидалось; админка открывается.
- [ ] 🤖 Скажите агенту: «Stage готов, продолжай». Внутри «Старт проекта» агент продолжит сам (режим заливки `stage-auto`, скачивание своего кода).

## Конец проекта

1. 🤖 Скажите агенту: «Stage больше не нужен». Агент проверит, что всё на проде и незалитого нет, и покажет, что есть только в базе stage — решаете вы.
2. 🖐 Подписка → «Удалить подписку» — БД, файлы, пользователь и сертификат уходят вместе с ней.
3. 🤖 Агент: `ACCESS.md` → «Stage: удалён <дата>», режим заливки, коммит. Конфиги в `.vscode/` остаются — новый stage их обновит.
