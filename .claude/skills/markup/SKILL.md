# Вёрстка макета на stage — `/markup`

Аргументы вызова: `$ARGUMENTS`

1. Выполнить одной командой, отдельным вызовом Bash, без `cd` и конвейеров:
   `node .claude/skills/project-ops/scripts/markup.mjs publish $ARGUMENTS`
   Без аргумента заливается изменённое в `markup/` против снимка stage; `--all` — всё.
2. Ответ пользователю — коротко: сколько файлов залито (или «изменений нет»), строка «Удалены локально…», если скрипт её вывел, и **ссылка из строки «Вёрстка:» отдельной строкой**, кликабельной.
   Ответ сервера не 200 — назвать код одной строкой (401 — браузер спросит пароль stage, это норма для клиента).
3. Ошибка скрипта (вёрстка не включена, нет `markup/`, нет `sftp-stage.json`) — показать её текст и что сделать; больше ничего не запускать.

Пароль stage в ответе не цитировать — только где лежит (`ACCESS.md` → «Пароль на stage»). Проверку вёрстки в браузере здесь не делать — это `layout-check` в задаче.
