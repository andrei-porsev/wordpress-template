# Шпаргалка по шаблону

Для человека: что умеет шаблон и что сказать агенту на каждом этапе — от старта до сдачи.
Подробности — в [`WORKFLOW.md`](./WORKFLOW.md); «почему так» по сайту — в [`DECISIONS.md`](./DECISIONS.md), по самому шаблону — в [`.claude/template/DECISIONS.md`](../.claude/template/DECISIONS.md).

Работаем в **Claude Code, открытом в папке проекта**: вкладка Code в десктопном приложении (локальная сессия) или `claude` в терминале.
Фразы ниже — примеры, а не заклинания: агент понимает и свои слова.
Пошаговые инструкции по темам (stage на своём VPS и др.) — команда **`/howto`**: без аргумента — список тем, `/howto stage` — инструкция целиком, `/howto stage 4` — с шага 4.
Вёрстка макета для клиента (`project.json` → `markup: true`) — **`/markup`**: заливает изменённое в `markup/` на stage и показывает ссылку на стартовую страницу (`/markup --all` — всё).

---

## Как устроено, в пяти строках

1. Агент правит код **локально**, хук сам заливает файл на сервер, проверяет сайт и откатывает при ошибке (режим в `ACCESS.md`).
2. Что записано в `ACCESS.md` (доступы, URL, Figma, Search Console) — агент **не переспрашивает**.
3. Решения проекта — в `DECISIONS.md`: агент им следует и не предлагает отброшенное заново.
4. Скиллы подключаются **стеками** под проект (`fse`, `woo`, `figma`, `design`, `motion`, `content`, `seo`…), лишние не забивают контекст.
5. Необратимое — только после вашего «да»: изменение БД, публикация, обновление скиллов, `git push`.

## 0. Новый проект

Скопировать папку шаблона в папку нового проекта, открыть в ней Claude Code. При первом запуске — «доверять папке: да»
и одобрить проектные хуки, иначе границы и автозаливка не работают.

## 1. Старт

```
Старт проекта.
```

Скилл `project-init` спросит блоками: проект и **объём работ** (дизайн в Figma, тексты, SEO), стек, свои слаги и префикс,
процессы, ограничения, **доступы** (SFTP, SSH/WP-CLI, URL, админка, Figma, БД, Search Console). Потом сам:
заполнит `INDEX.md` и `ACCESS.md`, сгенерирует whitelist, подключит стеки, проверит Node/PHP/хуки/связь с сервером
и (с вашего «да») прогонит тест заливки.

**Руками после старта:**
- `/mcp` → одобрить `playwright`; при Figma — у `figma` нажать Authenticate.
- Стек `seo` → вставить в `.claude/settings.json` фрагмент, который напечатал агент, и выполнить две команды установки плагина `claude-seo`; затем `/seo setup` (ключи Google и Gemini вводите вы).
- `phpcs` — по желанию, агент даст команду установки.

## 2. Сайт с сервера и карта

```
Скачай сайт с сервера и зафиксируй baseline.
Построй структуру проекта.
```

Первое — `sync-down`, коммит и тег `baseline` (точка отката), дамп БД на сервере. Второе — карта в `project-base/`:
пакет → фронт/бэк → файл → функции. Дальше агент ходит по карте, а не сканирует репозиторий.

```
git remote add origin <url>   # приватный репозиторий — делаете вы
git push -u origin main --tags
```

## 3. Сайт под ключ: этапы

Каждый этап закрываете своим «ок» — следующий строится на утверждённом. Порядок — `WORKFLOW.md` → 1.4.

| Этап | Что сказать агенту |
|------|--------------------|
| Бриф | `Заполни бриф .claude/product-marketing.md: задавай вопросы блоком.` |
| Структура | `Предложи структуру сайта: страницы, URL, меню. Сохрани в project-base/content/structure.md.` |
| Дизайн-система | `Создай в Figma файл и библиотеку: цвета, типографика, отступы, кнопки, карточки. Имена переменных — под слаги theme.json.` |
| Макеты | `Нарисуй в Figma главную в 375, 768 и 1440 по структуре и брифу. Стиль: <пара слов или ссылка-референс>.` |
| Макет в Claude Design (вместо Figma) | `/design главная: <бриф, референсы>. Покажи 3 направления.` → выбрать, доработать → `Сверстай этот макет в тему по правилу design.` (или handoff из claude.ai / экспорт в `project-base/design/`) |
| Дизайн-система клиента | `/design-sync` из этой темы — новые макеты сразу в цветах и шрифтах клиента. Поменяли `theme.json` — повторить. |
| Без макета | `Предложи план дизайна главной по frontend-design: палитра, шрифты, раскладка. Код — после моего «да».` |
| Анимации | `Сделай вход hero на GSAP: заголовок по словам, с reduced motion. Остальное — CSS.` (стек `motion`) |
| Тексты | `Напиши тексты для главной: сначала /seo content-brief по «<запрос>», потом copywriting. Сохрани в project-base/content/home.md.` |
| Картинки | `Сгенерируй hero-иллюстрацию для главной через /seo image-gen, 1600×900, WebP, с alt. Промпт запиши в content/images.md.` |
| Тема | `Перенеси переменные Figma в theme.json.` → `Сверстай главную по макету: шаблон, части, паттерны.` |
| Блоки | `Сделай блок «Калькулятор доставки»: динамический, Interactivity API, без jQuery.` |
| Магазин | `Настрой шаблоны Woo в блочной теме: каталог, товар, корзина, оформление — на блоках.` |
| Сдача | `Пройди чек-лист сдачи 2.6 и сохрани отчёт.` |

Ориентиры по запросу:
- **Блок с текстом** — укажите задачу блока («довести до кнопки “Рассчитать”»), запрос, лимиты длины из макета и сколько вариантов заголовка нужно.
- **Вёрстка по макету** — дайте ссылку на фрейм с `node-id`, если в `ACCESS.md` записан весь файл.
- Агент не выдумывает цифры, отзывы и сроки: где данных нет, будет `[уточнить: …]` — это вопросы клиенту.

## 4. Обычная задача (поддержка, правки)

```
Начинаем задачу: на странице товара убрать сайдбар и поднять отзывы выше.
```

Агент сам: `sync-down` → `git status` (чужие изменения — отдельным коммитом) → правка → хук заливает и проверяет →
проверка в браузере по брейкпоинтам → коммит `woo: …`. Длинная задача — заметка в `project-base/tasks/`.

Частые фразы:

| Нужно | Фраза |
|-------|-------|
| Стили | `Поправь отступы в hero на мобильном, скомпилируй SCSS и залей.` |
| Сборка блоков | `Собери блоки и залей build/.` |
| Только посмотреть на сервере | `Какие плагины активны и версия WP?` (WP-CLI на чтение — без вопросов) |
| Изменить что-то на сервере | `Сбрось кеш` / `Обнови пермалинки` — изменяющий WP-CLI спросит «да» и сам сделает дамп БД |
| Залить вручную (режим `manual`) | `Залей functions.php и style.css.` |
| Почему так сделано | `Почему тут паттерн, а не блок?` — ответ из `DECISIONS.md` |
| Зафиксировать решение | `Запиши в решения: формы — только Contact Form 7, клиент так хочет.` |
| Обновить карту | `Обнови структуру темы <slug>.` |

## 5. Скиллы и стеки

При старте сессии хук раз в сутки сверяет подключённые скиллы с апстримом и, если есть новое, агент предложит обновить.

| Нужно | Фраза или команда |
|-------|-------------------|
| Что подключено | `Покажи стеки.` → `skills-sync.mjs list` |
| Подключить | `Подключи стеки woo и content.` → `activate woo content` |
| Отключить | `Отключи стек figma.` → `deactivate figma` |
| Проверить обновления | `Проверь обновления скиллов.` → `check` |
| Обновить | `Обнови все скиллы: план, после моего «да» — применить и закоммитить.` → `update --all`, потом `--apply` (спросит подтверждение) |
| Не напоминать | `Отложи обновление wp-patterns.` → `ignore wp-patterns` |
| Новый скилл | `Добавь скилл <путь> из источника wordpress в стек fse.` → `add …` (спросит подтверждение) |

Команды — `node .claude/skills/project-ops/scripts/skills-sync.mjs <команда>` из корня. Подробно — `project-ops` → `skills.md`.

Стеки: `fse`, `blocks`, `interactivity`, `classic`, `builder`, `acf`, `woo`, `plugin`, `rest`, `wpcli`, `perf`, `phpstan`, `playground`,
`triage`, `figma`, `design`, `motion`, `content`, `quality`, `seo`. Свою доработку чужого скилла — отдельным правилом, не правкой копии: иначе он перестанет обновляться.

## 7. Сдача

```
Пройди чек-лист сдачи 2.6 и сохрани отчёт.
```

Агент проверит контент и разметку, индексацию, AI-видимость, скорость, доступность, магазин и технику,
сложит отчёт в `project-base/launch-<дата>.md`: пункт — статус — что сделать. Последним шагом — `/seo drift baseline <url>`.
Непройденный пункт без вашего решения = сайт не сдан.

## 8. После сдачи

| Когда | Фраза |
|-------|-------|
| Раз в месяц или после обновлений | `/seo drift compare <url>` — что сломалось в SEO с момента сдачи |
| Клиент правил сам | `Начинаем задачу: …` — `sync-down` покажет чужие правки отдельным коммитом |
| Обновления Woo/WP | `Перед апдейтом Woo поставь тег и проверь override-шаблоны на @version.` |

## Если что-то пошло не так

| Ситуация | Что делать |
|----------|-----------|
| Хук откатил заливку | Нормально: на сервере вернулась прежняя версия, агент чинит локально и заливает снова |
| Агент остановился после 3 попыток | Так задумано: прочитайте, что он пишет, и подскажите направление |
| Откатить файл | `Откати functions.php к вчерашнему состоянию и залей.` |
| Откатить задачу | `Откати коммиты задачи <…> через revert и залей затронутые файлы.` |
| Сломался контент или настройки | git их не вернёт — нужен дамп БД на сервере (`../claude-backup-*.sql` или бэкап хостинга) |
| Агент что-то заблокировал | Посмотреть `.claude/.state/audit.log`: кто, что и почему |
| Нет браузера или Figma | `/mcp` → статус серверов, одобрить или Authenticate |

## Что агент не сделает сам

- Не правит `.claude/settings.json`, хуки и `.git` — это делаете вы в редакторе.
- Не пишет файлы на сервере в обход заливки, не ходит в `wp-admin` дальше просмотра, не публикует контент.
- Не меняет БД без «да» и без дампа; не трогает ядро WP и чужие плагины — только хуки из своей темы или плагина.
- Не обновляет скиллы и не делает `git push` без подтверждения.
